# YCode 工具系统与 Agent Loop Spec

> 状态：已批准

## 背景

YCode 当前已经具备供应商无关的结构化消息、流式内容块、工具调用块、工具结果块和响应组装能力，也能解析模型流式返回的工具调用。但应用尚未提供可调用工具、工具注册与执行机制，也不会在模型请求工具后执行本地操作、回填结果并继续推理。

因此，当前 YCode 仍然是以文本对话为主的终端助手，无法自主读取和修改项目文件、搜索代码或运行项目命令。

## 目标

- 提供统一的工具定义、注册、查找、执行和结果表达能力。
- 首期提供读取文件、写入文件、精确编辑文件、执行命令、按模式查找文件和搜索代码内容六项核心工具。
- 工具只能在当前工作区边界内执行文件操作。
- 模型可以根据用户任务选择工具；YCode 执行工具并将结果回填对话上下文。
- 使用 ReAct 循环重复“模型推理—工具执行—结果回填”，直到模型正常结束或 Agent 到达终止状态。
- 通过供应商无关的 Agent 事件流暴露用户消息、模型过程文本、Thinking、工具执行过程、最终回复和错误。
- 支持同一轮中的安全读取工具并发执行，并以写入工具作为顺序屏障。
- 支持 plan-only 模式；该模式只允许调查和制定计划，不允许产生本地修改。
- 支持工具超时、用户取消、最大循环轮数和安全的失败反馈，避免异常破坏已提交的对话历史。
- 核心工具系统和 Agent Loop 保持供应商无关；本阶段只完成 Anthropic 的实际工具请求接入和端到端验证，OpenAI 保留现有纯聊天行为。

## 功能需求

- **F1：统一工具契约**  
  每个工具必须提供唯一名称、用途描述、参数 Schema、读写分类和执行能力。工具参数在执行前必须按照 Schema 校验；无效参数不得进入具体工具。

- **F2：工具注册与发现**  
  系统集中登记可用工具，拒绝重复名称，支持按名称查找，并能向模型请求提供当前允许使用的工具列表。未知工具调用必须转换为可理解的失败结果。

- **F3：工具访问分类**  
  本阶段只实现 `READ` 和 `WRITE` 两类。读取文件、查找文件和搜索内容属于 `READ`；写文件、编辑文件和执行命令属于 `WRITE`。分类接口允许以后扩展，但本阶段不实现更多类别或动态命令分析。

- **F4：工作区文件边界**  
  所有文件工具只能访问当前工作区。相对路径以工作区根目录为基准；绝对路径、父目录跳转、符号链接和 Junction 解析后不得越界。越界访问返回工具失败，不终止应用。命令工具的工作目录也必须位于工作区，但本阶段不对命令内部主动访问的路径提供文件系统沙箱。

- **F5：读取文件**  
  读取工具只接受 UTF-8 或 UTF-8 BOM 文本，拒绝二进制及其他编码。支持按起始行和行数分页，返回带行号的内容，以及路径、返回范围、总行数和截断状态。单次最多返回 2,000 行或 100 KiB。

- **F6：写入文件**  
  写入工具可以创建新文件，也可以在显式允许覆盖时完整替换已有文件。覆盖默认关闭；父目录不存在时返回错误，不自动创建目录。写入使用 UTF-8 无 BOM。写入必须通过同目录临时文件和原子替换完成，失败时不得留下部分文件。

- **F7：精确编辑文件**  
  编辑工具使用原文的字面唯一匹配替换，不使用正则。匹配零次或多次时不修改文件，并返回清楚的可重试错误。编辑保留原文件的 UTF-8 BOM 状态和换行风格，通过原子替换提交结果。

- **F8：执行命令**  
  命令工具公开名称为 `run_command`，本阶段只使用 PowerShell。支持可选的工作子目录，默认工作区根目录；工作目录必须已存在且位于工作区内。工具返回退出码、stdout、stderr、耗时和截断信息，stdout 与 stderr 合计最多保留 100 KiB。默认超时 120 秒；超时或取消时终止 PowerShell 及其子进程树。

- **F9：按模式查找文件**  
  文件查找使用工作区相对的 POSIX 风格 Glob，统一使用 `/`，支持 `*`、`?` 和 `**`，只返回文件。查找遵循 `.gitignore`，始终排除 `.git/`，保留未被忽略的点目录。结果按相对路径稳定排序，默认最多 200 条，硬上限 1,000 条。

- **F10：搜索代码内容**  
  内容搜索使用逐行正则表达式，不支持跨行匹配。支持限定搜索路径、文件模式、大小写和结果数量。结果包含相对路径、行号和匹配行，按路径与行号稳定排序。无效正则返回工具失败；非 UTF-8 或二进制文件跳过并统计。默认最多 100 个匹配，硬上限 500 个。

- **F11：统一工具执行**  
  工具执行统一处理参数校验、名称查找、超时、结果大小限制和安全错误转换。文件、编辑和搜索工具默认超时 30 秒，命令默认超时 120 秒。可预期的工具失败作为结构化结果返回模型，使其能够调整方案，而不是中断整个 Agent。

- **F12：结构化工具结果**  
  工具执行结果包含主要内容、成功/失败标记和结构化元信息。Agent 将结果关联原工具调用 ID，转换成用户角色的工具结果消息，加入本轮临时上下文。模型需要的元信息以稳定格式进入工具结果内容；完整结构同时通过事件流提供给上层消费者。

- **F13：ReAct Agent Loop**  
  一轮循环由“请求模型、接收并组装完整响应、判断停止原因、执行工具、回填结果”组成。模型返回工具调用时继续；返回正常结束时产生最终回复。默认最多执行 10 轮，并允许应用装配时覆盖该上限，不增加用户配置项。

- **F14：Agent 终止状态**  
  Agent 对外只暴露四种终止结果：正常完成、达到迭代上限、用户取消和异常。模型工具调用表示继续，模型正常结束表示完成；达到输出上限、内容过滤、停止序列、未知停止原因或不一致的工具调用状态均归入异常。

- **F15：会话事务**  
  已完成历史由会话持有。当前用户消息、中间模型工具调用、工具结果和最终回复只存在于本轮临时上下文。整轮正常完成后一次性提交；迭代上限、取消或 Agent 异常时不提交残缺历史。已经完成的文件或命令副作用不自动撤销。

- **F16：工具批次调度**  
  同一模型响应中的连续读取工具组成并发批次；写入工具作为并发屏障，等待此前读取结束后逐个串行执行；写入后的读取不得提前。执行结果按模型原始调用顺序回填。并发读取的完成事件按实际完成时间输出。

- **F17：Agent 事件流**  
  对外事件流至少表达用户消息、模型 Thinking、模型过程文本、工具执行开始、工具执行结果、模式变化、最终回复、取消和 Agent 错误。事件携带供应商无关的完整结构化数据，上层决定展示摘要。Provider 的单次响应结束事件不得直接作为整次 Agent 完成事件。

- **F18：过程文本与最终回复**  
  工具调用轮中的模型文本作为过程事件实时展示，但不并入最终回复。最后一个不再请求工具的模型消息作为独立最终回复，并在完成后进行 Markdown 渲染。

- **F19：plan-only 模式**  
  用户通过 `/plan` 进入 plan-only，通过 `/agent` 返回正常模式。plan-only 只向模型提供读取类工具，并在执行边界再次拦截写入类工具；使用最小模式提示要求模型只调查并输出实施计划。计划输出后继续保持 plan-only，直到用户显式切换。模式仅在当前进程保存。

- **F20：模式状态提示**  
  输入区域左侧保留帮助提示，右下角持续显示 `mode: agent` 或 `mode: plan-only`。窄终端优先保证模式信息可识别。模式切换同时产生可消费事件和一次可见确认。

- **F21：最小系统指令**  
  Agent 请求包含供应商无关的最小系统指令，说明工作区、当前 Shell、可用工具、失败调整和当前模式约束。本阶段不建设复杂提示词组装系统。

- **F22：Provider 边界**  
  工具系统、调度、Agent Loop 和事件流不得依赖供应商 SDK 类型。可用工具列表由注册系统提供，并作为模型请求的一部分传入 Provider。现有结构化工具调用解析和消息块继续复用。本阶段只完成 Anthropic 的工具请求接入；OpenAI 保留现有纯聊天行为，不进行工具适配或其他开发。

## 非功能需求

- **N1：供应商隔离**  
  工具定义、执行结果、Agent 状态和对外事件不得包含 Anthropic SDK 类型或协议事件。供应商格式转换只存在于 Provider 边界。

- **N2：异步与响应性**  
  模型流、工具执行和事件消费期间，终端输入输出与计时刷新不得被同步阻塞。读取工具并发和命令等待必须保持事件循环可响应。

- **N3：取消传播**  
  外部取消必须沿 Agent Loop、工具批次和子进程传播。取消完成后不得继续启动新的工具或模型请求；终端必须恢复到可输入状态。

- **N4：资源有界**  
  模型轮数、工具执行时间、文件读取量、搜索结果数量和命令输出均必须有硬上限。截断必须显式可见，不能静默丢弃内容。

- **N5：确定性**  
  文件查找、内容搜索和工具结果回填顺序必须稳定。并发执行不得改变模型原始工具调用与结果的对应关系。

- **N6：并发安全**  
  只有同一连续批次中的读取工具可以并发；写入工具不得重叠执行。写入屏障前后的工具观察顺序必须与模型调用顺序一致。

- **N7：文件安全**  
  文件工具必须在执行前完成规范化路径和真实目标检查。路径校验与实际操作之间应尽量避免使用不同目标；临时文件只能创建在已验证的目标目录内。

- **N8：写入完整性**  
  文件创建、完整覆盖和精确编辑不能留下部分写入。替换失败、超时或取消时，原目标文件应保持可用，并清理本次生成的临时文件。

- **N9：错误安全**  
  返回模型、TUI 或 CLI 的错误不得包含 API Key、认证头、完整环境变量、未整理的异常对象或 traceback。工具调用参数中的大段文件内容不得被错误信息无条件回显。

- **N10：会话一致性**  
  只有完整正常结束的 Agent 轮次可以进入已提交历史。失败或取消不得破坏此前成功对话，也不得生成缺少调用或结果对应关系的历史。

- **N11：事件完整性**  
  每个已开始的工具执行必须产生对应的完成、失败或取消结果。最终回复事件在一次用户对话中最多产生一次，并且只能在 Agent 正常结束后出现。

- **N12：可测试性**  
  工具、注册、执行、调度、Agent 状态转换、Provider 请求接入和 UI 事件消费必须能使用临时工作区、虚拟工具和本机模拟模型服务测试，不依赖真实 API Key 或外部网络。

- **N13：现有行为兼容**  
  不使用工具的 Anthropic 对话应保持现有 Thinking、文本流、Markdown、计时和历史事务行为。OpenAI 的现有纯聊天路径不得因工具系统发生回归。

- **N14：平台范围**  
  本阶段正式支持范围保持 Windows。命令工具使用 PowerShell，不声明或验收 macOS/Linux 支持；公开工具名称不阻止未来通过独立功能增加其他命令后端。

- **N15：依赖控制**  
  参数 Schema 与配置复用项目现有的数据校验能力；文件忽略规则只新增必要的轻量依赖。不得引入完整 Agent 框架、插件框架或跨平台 Shell 框架。

- **N16：可观测性**  
  用户能够通过事件与终端显示判断当前模式、模型是否仍在处理、正在执行哪个工具、工具是否成功、结果是否截断以及整轮为何终止。

## 不做的事

- OpenAI 工具定义转换、工具请求接入、Agent Loop 验收或其他 OpenAI Provider 开发。
- 新增 Anthropic/OpenAI 以外的 Provider。
- 引入 LangChain、LangGraph、SDK Tool Runner 或其他完整 Agent 框架。
- 复杂 System Prompt 拼装、提示模板系统、提示缓存或上下文压缩。
- 完整权限策略、逐次用户审批、命令白名单、风险等级和持久化授权。
- 对 PowerShell 命令提供真正的文件系统、网络、注册表或进程沙箱。
- macOS、Linux、Bash、`/bin/sh` 或其他命令后端的实现与验收。
- 子代理、任务委派、把 Agent 注册成工具或递归 Agent 调用。
- MCP、Skill、插件、动态工具目录扫描或第三方工具加载。
- 除六个核心工具外的删除文件、移动文件、创建目录、Git 专用操作等额外工具。
- 非 UTF-8 文本的自动编码检测、二进制文件读取或编辑。
- 多行内容正则搜索或基于正则的文件编辑。
- 自动备份、撤销历史、文件系统事务或取消后的副作用回滚。
- 工具调用和会话历史的跨进程持久化。
- plan-only 的 `/approve`、计划对象保存、自动退出或自动执行。
- 用户可配置的轮数、超时、输出上限或搜索后端。
- `rg`、外部 Git 命令或其他系统搜索程序作为搜索后端。
- PowerShell stdout/stderr 的逐行实时事件；本阶段只在命令结束、失败、超时或取消后产生工具结果。
- 根据 PowerShell 命令文本推断其实际读写性质；命令工具统一视为写入类。
- 读取工具之间的依赖图分析或跨模型轮次的投机执行。
- 自动重试 Provider 请求或自动重复执行失败的写入工具。
- 真实 API Key 的自动化测试、外部网络调用或未经用户发起的 Git commit。
- YCode 产品、Python 包、CLI 命令或配置目录的改名。

## 验收标准

- **AC1（F1–F3）**  
  六个工具都能提供唯一名称、描述、参数 Schema 和读写分类；重复注册被拒绝；按名称可以找到正确工具；未知名称返回结构化失败结果。

- **AC2（F4）**  
  文件工具可以访问工作区内的合法相对路径及解析后仍位于工作区内的绝对路径；工作区外的绝对路径以及通过 `..`、符号链接或 Junction 越界的目标均被拒绝，目标文件和工作区外文件保持不变。

- **AC3（F5）**  
  读取 UTF-8 和 UTF-8 BOM 文件时得到带行号的指定范围及正确元信息；分页和 2,000 行/100 KiB 上限生效；非 UTF-8、二进制、目录和不存在路径返回明确失败。

- **AC4（F6）**  
  写入新文件成功；已有文件在未明确覆盖时保持不变并返回错误；明确覆盖时完整原子替换；父目录不存在、目标为目录或替换失败时不留下部分文件或临时文件。

- **AC5（F7）**  
  原文恰好匹配一次时只替换该处，并保持 BOM 与换行风格；匹配零次、多次或参数无效时不修改文件，并向模型提供可据此重试的原因。

- **AC6（F8）**  
  命令在工作区或指定合法子目录中由 PowerShell 执行，结果包含退出码、stdout、stderr、耗时和截断状态；非法工作目录被拒绝；超时或取消后 PowerShell 及其子进程不再运行。

- **AC7（F9）**  
  POSIX Glob 能正确处理 `*`、`?` 和 `**`，只返回工作区内文件；结果使用 `/`、稳定排序、遵循 `.gitignore`、跳过 `.git/`，并遵守默认数量和硬上限。

- **AC8（F10）**  
  内容搜索能按逐行正则返回相对路径、行号和匹配文本，正确处理大小写、路径和文件模式；结果稳定排序并遵守数量上限；无效正则失败，非 UTF-8/二进制文件被跳过并统计。

- **AC9（F11）**  
  工具参数缺失、类型错误、未知工具、文件错误、搜索错误、命令非零退出和工具超时均被转换为结构化工具结果，不导致 Agent 进程崩溃；模型在下一轮可以看到失败信息。

- **AC10（F12）**  
  每个执行结果都与原工具调用 ID 正确关联，并作为工具结果加入本轮模型上下文；模型收到主要内容和必要元信息；TUI/CLI 事件消费者可读取完整结构化结果。

- **AC11（F13）**  
  本机模拟模型依次返回多个工具调用轮和最终回复时，Agent 能执行、回填并继续请求，最后只产生一次最终回复；请求次数和每轮消息上下文符合 ReAct 顺序。

- **AC12（F13、F14）**  
  连续 10 轮工具调用后 Agent 以迭代上限终止且不发最终回复；正常结束映射为完成；输出上限、内容过滤、停止序列、未知原因和矛盾状态均映射为异常。

- **AC13（F15）**  
  正常 Agent 轮次一次性提交用户消息、中间工具调用、工具结果和最终回复；Provider 错误、结构错误、达到轮数上限或用户取消时，本轮临时历史不提交，此前成功历史保持不变。

- **AC14（F16）**  
  连续读取工具确实并发执行；写入工具等待此前读取完成并阻止后续读取提前；多个写入工具不重叠。完成事件按实际完成时间出现，回填模型的工具结果仍按原调用顺序排列。

- **AC15（F17）**  
  一次完整 Agent 对话可以观察到用户消息、Thinking、过程文本、工具开始、工具结果和最终回复事件；模式切换、取消和错误也有明确事件；事件中不存在供应商 SDK 类型。

- **AC16（F17、F18）**  
  中间 Provider 请求的结束不会让 UI 提前完成；工具调用轮的过程文本实时可见但不混入最终回复；最后无工具调用的模型消息独立完成 Markdown 渲染。

- **AC17（F19）**  
  `/plan` 后模型请求只获得读取类工具，写入和命令调用在执行边界仍被拒绝；Agent 最终输出计划且模式不自动退出。执行 `/agent` 后写入类工具恢复可用。

- **AC18（F20）**  
  等待输入时右下角持续显示正确模式；切换模式后状态立即更新并出现一次确认；窄终端中模式文本仍可识别，帮助提示与输入布局不发生破坏性错位。

- **AC19（F21）**  
  普通模式请求包含工作区、PowerShell 和工具使用的最小系统指令；plan-only 请求包含只调查和输出计划的约束；提示中不包含复杂模板、供应商对象或敏感配置。

- **AC20（F22）**  
  Anthropic 本机模拟服务收到的请求包含注册系统提供的工具定义，Schema 与工具参数要求一致；返回的分片工具调用继续由现有结构化事件和消息组装逻辑正确解析。

- **AC21（F22、N1、N13）**  
  工具系统和 Agent Loop 代码不导入 Anthropic/OpenAI SDK 类型；不使用工具的 Anthropic 对话继续保持现有体验；OpenAI 现有纯聊天单元、集成和端到端行为保持通过，且请求中不新增工具定义。

- **AC22（N3、N10、N11）**  
  模型流、并发读取、写入等待和 PowerShell 执行各阶段都可以被用户取消；取消后不再启动新工具或模型请求，每个已开始工具都有可观察终态，临时历史回滚，终端恢复输入。

- **AC23（N4、N9）**  
  文件、搜索和命令产生超量结果时明确标记截断且内存和模型上下文保持在规定上限内；错误与事件输出中不存在 API Key、认证头、完整环境变量、traceback 或无条件回显的大段敏感参数。

- **AC24（整体端到端）**  
  在真实 Windows PTY 会话中，用户可以让模型读取项目、搜索代码、修改文件并运行命令；界面按顺序显示过程和工具摘要，最终得到模型回复。plan-only、工具失败、取消、轮数上限和退出后终端恢复均有真实交互验证。
