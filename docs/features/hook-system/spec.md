# YCode Hook 系统 Spec

## 背景

YCode 当前具备 Agent Loop、工具权限控制、上下文压缩、会话管理和工具调度能力，
但这些流程的扩展点主要固化在实现代码中。项目无法通过声明式配置，在生命周期
节点执行自动化任务、注入模型上下文或动态参与工具权限决策。

本功能引入项目级 Hook 系统。Hook 使用“事件 + 可选条件 + 动作”描述规则，从
`.ycode/hooks.yaml` 加载，并嵌入会话、用户任务、模型消息、工具执行、上下文压缩
和 Agent 错误等关键节点。第一期以验证核心功能链路为目标，不建设生产级可靠性能力。

## 目标

- 允许项目通过 YAML 声明 Hook，无需修改 YCode 实现代码。
- 使用统一事件上下文和简单条件语法筛选规则。
- 支持 Shell、System Reminder、HTTP 和预留子 Agent 四类动作。
- 允许同步的工具执行前 Shell Hook 仿照 Claude Code，动态返回 `allow`、`deny` 或
  `ask`。
- 将 Hook 权限结果与现有权限流程结合，同时保持参数校验、工作区路径边界、危险
  命令检查和 plan-only 限制不可绕过。
- 将 Hook 运行失败与 Agent 主流程隔离，并提供可定位的日志和启动配置诊断。
- 控制第一期复杂度，不引入完整表达式引擎、持久化执行状态或真实子 Agent 调用。

## 功能需求

- **F1：项目配置发现**  
  YCode 从当前工作目录向上查找最近的 `.ycode/hooks.yaml`，并在应用启动时加载。
  不存在配置时，Hook 系统使用空规则运行，不影响正常使用。

- **F2：规则结构**  
  每条规则由唯一 ID、启用标记、事件、可选条件和一个动作组成。事件和动作必须存在；
  `enabled` 表示是否启用该规则，省略时默认为 `true`；省略条件表示无条件匹配。多条
  规则按照 YAML 声明顺序处理。禁用规则不求值条件、不执行动作，也不产生权限决定。

- **F3：生命周期事件**  
  第一期支持以下事件：

  - `session.start`：YCode 会话可用后触发。
  - `session.end`：应用关闭过程中触发。
  - `turn.start`：一次完整用户任务开始时触发。
  - `turn.end`：用户任务正常完成、取消、报错或达到轮数上限时触发。
  - `message.before_send`：每次完整模型请求发送前触发。
  - `message.after_receive`：每次模型完整响应组装后触发；流式增量不触发。
  - `tool.before_execute`：工具通过不可绕过的硬安全检查、但尚未执行时触发。
  - `tool.after_execute`：工具实际执行完成后触发，成功与失败使用同一事件。
  - `context.compacted`：上下文成功压缩后触发。
  - `agent.error`：导致当前用户任务失败的 Agent、Provider、上下文或工具流程错误
    发生时触发。

- **F4：任务结束状态**  
  `turn.end` 始终触发，并携带 `completed`、`cancelled`、`error` 或
  `limit_reached` 状态及适用的错误信息。任务失败时先触发 `agent.error`，再触发
  `turn.end`。Hook 自身错误不产生 `agent.error`。

- **F5：条件组合**  
  一条规则的多个条件只能选择“全部满足”或“任一满足”之一，不允许在同一规则内
  混合两种逻辑组合，也不支持嵌套逻辑表达式。

- **F6：条件匹配**  
  条件通过点路径读取事件上下文，支持对象字段和数组索引，例如
  `tool.arguments.path` 与 `tool.arguments.files.0`。支持以下操作符：

  - `exact`：值精确相等。
  - `glob`：字符串 Glob 全匹配。
  - `regex`：字符串正则匹配。
  - `not`：包装并取反一种正向匹配。

  字段不存在时条件不匹配；即使使用 `not`，缺失字段也不得转化为匹配。Hook 可复用
  权限系统适合共享的底层匹配能力，但不得扩展现有权限配置对外开放的操作符。

- **F7：事件上下文**  
  所有事件提供事件名和当前项目路径，并按事件类型提供可用的会话、任务、消息、工具、
  文件、压缩报告、状态和错误信息。工具参数支持通过任意深度的点路径访问。

- **F8：模板替换**  
  Shell 命令、System Reminder 内容以及 HTTP 的 URL、请求头和请求体支持
  `{{ field.path }}` 变量。模板只进行文本替换，不支持表达式、函数、过滤器、判断或
  循环。字段不存在时替换为空串；非文本值转换为稳定的文本表示。

- **F9：Shell 动作**  
  Shell 动作通过独立 Hook 执行环境运行。默认工作目录为项目根目录，不进入工具权限
  审批，也不触发新的 Hook。Shell 支持同步和后台异步执行，普通标准输出和错误输出
  写入 Hook 日志。加载包含 Shell 动作的配置时，启动诊断明确提示其具有执行外部操作
  的能力。

- **F10：工具执行前权限控制**  
  `tool.before_execute` 的同步 Shell 动作可以在标准输出中返回单个 JSON 对象，其中
  仅识别：

  - `permissionDecision`：`allow`、`deny` 或 `ask`。
  - `permissionDecisionReason`：决定原因。

  YAML 规则也可声明固定权限决定。Shell 返回有效动态决定时优先于该规则的固定决定；
  动作超时、执行失败或输出非法时，忽略动态决定并回退到固定决定；没有固定决定则视为
  不干预。`ask` 用于将原本可能自动允许的调用升级为人工审批；如果现有权限流程也要求
  审批，两者合并为一次审批，不重复询问。

- **F11：权限流程结合**  
  工具调用首先经过参数合法性、工作区路径边界、危险命令和 plan-only 等不可绕过检查。
  通过后执行 `tool.before_execute` Hook：

  - `allow`：跳过普通项目权限规则和人工审批。
  - `deny`：阻止工具执行，并将原因作为工具结果反馈给模型。
  - `ask`：确保调用进入一次现有人工审批。
  - 无决定：继续现有权限流程。

  多条命中规则按 `deny > ask > allow > 无决定` 汇总。得到 `deny` 后立即停止后续执行前
  规则。最终每个工具调用最多产生一次人工审批。

- **F12：工具执行后行为**  
  `tool.after_execute` 只针对真正进入工具执行器的调用触发，无论工具结果成功或失败。
  被硬安全检查、权限系统或 Hook 拒绝而未实际执行的调用不触发该事件。

- **F13：System Reminder 动作**  
  提示词动作将模板结果包装成临时 System Reminder：

  ```xml
  <system-reminder>
  Hook rule: lint-result
  Hook event: tool.after_execute

  检查发现代码格式不符合项目要求，请先执行格式化。
  </system-reminder>
  ```

  Reminder 内容按 XML 文本规则安全转义，作为系统级补充提供给模型，不作为用户消息，
  也不写入持久会话历史。它只进入下一次模型请求并在使用后清除；
  `message.before_send` 产生的 Reminder 进入当前请求。`session.end` 不允许使用该动作。

- **F14：HTTP 动作**  
  HTTP 动作支持 `GET`、`POST`、`PUT`、`PATCH` 和 `DELETE`，可配置 URL、请求头及文本
  或 JSON 请求体，并支持同步或后台异步执行。仅 2xx 响应视为成功；响应内容只写入
  日志，不参与权限决定或 System Reminder 注入。加载包含 HTTP 动作的配置时提示其
  外部通信能力。

- **F15：子 Agent 动作占位**  
  配置模型和动作执行入口保留 `agent` 类型。规则命中时不启动子 Agent，只在终端输出
  包含规则 ID 的“子 Agent Hook 尚未实现”信息，并将该次动作视为已执行。

- **F16：单次执行与运行时状态**  
  每条规则具有加载时固定的 `enabled`、`once` 配置和当前应用会话内的 `executed`
  运行时状态。`enabled: false` 时始终跳过规则。`executed` 初始为 `false`，不从 YAML
  配置，也不持久化。启用规则的事件和条件匹配后、动作启动前，将 `executed` 设置为
  `true`。当 `once: true` 且 `executed: true` 时，后续事件不再触发该规则。动作失败、
  异常、超时或异步任务被取消均不恢复 `executed`；条件未匹配时不改变状态。
  `once: false` 时，`executed` 不限制后续触发。YCode 重启后所有规则的 `executed` 重置
  为 `false`。

- **F17：异步与超时控制**  
  只有 Shell 和 HTTP 动作支持异步执行。参与权限决定的动作与 System Reminder 动作
  必须同步。同步和异步动作的默认超时均为 30 秒，规则可以覆盖该值。异步动作启动后
  不阻塞 Agent 主流程。

- **F18：异步任务退出处理**  
  应用退出时先执行 `session.end` Hook，再等待后台 Hook 任务最多 3 秒；期限内未完成
  的任务被取消，不继续阻塞退出。

- **F19：错误隔离**  
  Hook 条件求值、模板替换或动作执行发生运行期错误时，只记录带规则 ID、事件名和错误
  摘要的日志，不中断 Agent 主流程。执行前 Hook 的动态权限处理失败按“无动态决定”
  处理，不得产生隐式拒绝或隐式允许。

- **F20：配置校验与降级**  
  加载时校验事件名、规则 ID、动作类型、条件结构、操作符、动作必填字段和以下约束：

  - 权限决定只能用于 `tool.before_execute`。
  - 参与权限决定的动作不能异步。
  - System Reminder 动作不能异步，也不能用于 `session.end`。
  - `agent` 仅按占位语义接受。
  - 同一配置中的规则 ID 必须唯一。

  YAML 无法解析或顶层结构非法时，整份配置不加载，但 YCode 继续启动。单条规则非法或
  ID 重复时只跳过该规则，其他合法规则继续加载；重复 ID 保留先出现的规则。不得执行
  任何部分解析或部分校验的动作。

- **F21：诊断与日志**  
  配置诊断在启动时汇总显示一次并写入日志，包含配置路径、规则序号、可识别的规则 ID
  和具体字段问题，后续事件不重复提示。运行日志能够区分规则未匹配、成功、失败、超时、
  跳过和权限决定等结果。

## 非功能需求

- **N1：主流程错误隔离**  
  Hook 运行期故障不得中断 Agent 主流程。错误应转换为日志和可观测的执行结果。工具
  执行前动态权限决定失败时，按无动态决定处理，并回退到规则的固定决定。

- **N2：硬安全边界不可绕过**  
  Hook 返回 `allow` 也不能绕过工具参数校验、工作区路径限制、危险 PowerShell 检查和
  plan-only 限制。Hook Shell 是用户声明的独立外部动作，不属于 Agent 工具调用，不进入
  工具权限系统。

- **N3：确定性**  
  相同事件上下文、规则顺序和运行状态应产生相同的匹配与权限结果。规则按照配置声明
  顺序执行；工具执行前权限优先级固定为 `deny > ask > allow > 无决定`。

- **N4：有限表达能力**  
  条件系统不发展为通用表达式引擎。逻辑组合只能选择全部满足或任一满足；模板只支持
  点路径变量替换；不执行模板中的代码。

- **N5：执行时序**  
  同步 Hook 必须在对应生命周期节点完成后，主流程才继续。异步 Hook 不阻塞主流程。
  工具拦截、权限决定和 System Reminder 注入不得异步执行。

- **N6：单次执行确定性**  
  `enabled` 和 `once` 在规则加载后保持固定。禁用规则不得产生运行时副作用。启用规则
  首次匹配并准备启动动作时，必须先将运行时 `executed` 设置为 `true`，再启动同步或
  异步动作。动作失败、超时或取消不恢复状态，避免重复外部副作用。

- **N7：资源收尾**  
  后台 Shell 和 HTTP Hook 纳入应用级任务管理。关闭时先执行 `session.end` Hook，再等待
  后台任务最多 3 秒，之后取消未完成任务，不无限阻塞退出。

- **N8：日志可定位性**  
  每条运行日志至少包含事件名、规则 ID、动作类型和执行结果。失败日志包含简短错误原因，
  但不得无边界记录消息正文、工具结果、HTTP 响应或可能含有敏感信息的完整上下文。

- **N9：配置容错**  
  Hook 配置错误不得阻止 YCode 启动。整份文件不可解析时禁用该文件；单条规则非法时只
  跳过该规则。诊断必须能够定位配置文件、规则序号、可识别的规则 ID 和错误字段。

- **N10：外部操作可见性**  
  加载 Shell 或 HTTP 动作时，必须在启动诊断中提醒用户该项目配置能够执行本地命令或
  发起网络请求。提示仅显示一次，不在每轮重复。

- **N11：兼容现有流程**  
  Hook 系统不得破坏现有权限审批、工具调度、取消、上下文压缩、会话保存和 Anthropic
  Agent 工具循环。被允许的工具继续使用现有执行器和结果回填机制。

- **N12：供应商边界**  
  Hook 核心的事件、规则、上下文和动作模型保持供应商无关；当前只接入并验证 Anthropic
  Agent 路径。

- **N13：功能性可验证**  
  使用代表性自动化测试验证配置加载、条件匹配、模板替换、`once/executed`、权限合并、
  动作执行、System Reminder 注入及错误隔离。CLI、Agent Loop 和工具拦截使用少量真实
  端到端场景验证主链路，不追求生产级场景矩阵。

## 不做的事

- 不支持用户级或全局 Hook 配置，也不合并多份配置。
- 不支持 Hook 配置热加载；修改配置后需重新启动 YCode。
- 不扩展现有权限配置公开语法；权限规则继续只支持 `exact` 和 `glob`。
- 不允许 Hook 绕过参数校验、工作区路径边界、危险命令检查或 plan-only 限制。
- 不实现完整表达式语言、任意嵌套布尔逻辑、模板函数、过滤器、判断、循环或代码执行。
- 不修改工具参数；工具执行前 Hook 只能返回 `allow`、`deny`、`ask` 或不干预。
- 不让异步动作返回权限决定或注入 System Reminder。
- 不允许 HTTP 响应参与权限决定、System Reminder 注入或 Agent 控制。
- 不将 System Reminder 写入用户消息或持久会话历史。
- 不为流式文本、Thinking 增量或每个模型内容块触发 Hook。
- 不为被安全策略、权限系统或 Hook 拒绝且未实际执行的工具调用触发
  `tool.after_execute`。
- 不把单个工具的普通失败升级为 `agent.error`；只有导致当前用户任务失败的流程错误
  触发该事件。
- 不因 Hook 自身错误再次触发 `agent.error`。
- 不实现子 Agent 创建、调度、上下文传递或结果回填；第一期只保留动作类型和执行入口，
  并打印占位信息。
- 不持久化 `executed` 状态、Hook 执行历史或审计记录；重启后状态清空。
- 不提供 Hook 管理命令、终端编辑器、图形界面或运行时启停功能。
- 不实现 Hook Shell 的操作系统沙箱、受限账户或容器隔离；项目 Hook 配置按受信任的
  可执行配置处理，并在启动时提示风险。
- 不实现后台任务重试、失败补偿或进程退出后的续跑。
- 不做压力测试、性能基准、长时间稳定性运行或大规模并发验证。
- 不做复杂故障注入、网络异常矩阵、跨平台兼容矩阵或生产环境验证。
- 不建设生产级审计、日志轮转、指标监控、分布式任务管理或崩溃恢复。
- 不穷举所有事件、操作符、动作和权限状态的笛卡尔组合，只验证代表性路径。
- 不调用真实付费外部服务；HTTP 和模型交互优先使用本地测试服务及现有测试替身。
- 不新增或扩展 OpenAI 专用配置、Provider 适配、协议转换或验收场景；现有 OpenAI
  路径只做回归保护。

## 验收标准

- **AC1：配置发现与加载**  
  在不同子目录启动 YCode 时，能够发现最近的 `.ycode/hooks.yaml`；配置不存在时正常
  启动且不触发 Hook。

- **AC2：配置容错**  
  YAML 无法解析或顶层结构非法时，整份配置不加载但应用正常启动；单条规则非法或 ID
  重复时，仅跳过对应规则，其他合法规则仍能执行。

- **AC3：启动诊断**  
  非法规则的启动诊断包含配置路径、规则序号、可识别的规则 ID 和具体字段；包含 Shell
  或 HTTP 动作时显示一次外部操作风险提示，后续用户任务不重复显示。

- **AC4：生命周期事件**  
  会话、用户任务、模型消息、工具执行、上下文压缩和 Agent 错误事件均在约定节点触发。
  模型流式增量不触发消息 Hook。

- **AC5：任务结束状态**  
  用户任务正常完成、取消、失败或达到轮数上限时，`turn.end` 分别携带正确状态。任务
  失败时可观察到 `agent.error` 先于 `turn.end`。

- **AC6：条件逻辑**  
  无条件、全部满足和任一满足规则按定义执行；同一规则混用逻辑组合时，该规则被跳过并
  产生明确诊断。

- **AC7：匹配操作符**  
  `exact`、`glob`、`regex` 和包装正向操作符的 `not` 均能正确匹配。点路径可访问嵌套
  对象与数组元素；字段缺失时，包括使用 `not` 时，均判为不匹配。

- **AC8：模板替换**  
  Shell、System Reminder 和 HTTP 动作能够使用 `{{ field.path }}` 引用事件上下文；
  缺失字段替换为空串，非文本值产生稳定文本，不执行任何模板表达式或代码。

- **AC9：Shell 动作**  
  Shell Hook 以项目根目录为默认工作目录，通过独立执行器运行，不触发工具权限审批或
  递归 Hook；同步、异步、默认超时和自定义超时行为符合定义。

- **AC10：动态权限输出**  
  同步 `tool.before_execute` Shell 输出合法 JSON 时，能够产生 `allow`、`deny` 或
  `ask` 及对应原因。非法输出、异常或超时时忽略动态决定，并回退到规则固定决定或现有
  权限流程。

- **AC11：权限流程合并**  
  `allow` 能跳过普通权限规则和人工审批，`ask` 能把原本自动允许的调用升级为一次人工
  审批，`deny` 能阻止执行并把原因反馈给模型。现有权限系统与 Hook 同时要求审批时，
  用户只被询问一次。

- **AC12：权限优先级与短路**  
  多条执行前规则按声明顺序运行，并按照 `deny > ask > allow > 无决定` 汇总。出现
  `deny` 后不再执行后续规则，工具不产生副作用。

- **AC13：硬安全边界**  
  即使 Hook 返回 `allow`，无效参数、工作区路径越界、危险 PowerShell 命令和 plan-only
  禁止的调用仍被拒绝。

- **AC14：工具执行后事件**  
  工具真正执行后，无论结果成功或失败，均触发一次 `tool.after_execute`，并提供结果错误
  状态和内容。执行前被拒绝的调用不触发该事件。

- **AC15：System Reminder**  
  提示词动作生成带事件名、规则 ID 和安全转义内容的 `<system-reminder>`，只进入下一次
  模型请求，使用后清除，且不写入持久会话历史。`message.before_send` 生成的内容进入
  当前请求。

- **AC16：HTTP 动作**  
  支持约定的五种 HTTP 方法、请求头、文本及 JSON 请求体。2xx 记录为成功，非 2xx、
  网络错误和超时记录为失败；响应不改变权限结果或模型上下文。

- **AC17：子 Agent 占位**  
  `agent` 动作命中时不创建子 Agent，只在终端打印包含规则 ID 的“子 Agent Hook 尚未
  实现”信息，主流程继续运行。

- **AC18：单次执行状态**  
  每条规则加载时具有固定 `enabled`、`once` 和初始为 `false` 的运行时 `executed`。
  `enabled: false` 的规则不触发；启用规则在事件和条件匹配后、动作启动前将 `executed`
  设为 `true`；当 `once` 与 `executed` 同时为真时不再触发。动作失败、超时或取消不
  恢复状态，重启后状态重置。

- **AC19：异步执行与退出**  
  异步 Shell 和 HTTP 不阻塞 Agent 主流程。应用退出时先运行 `session.end` Hook，再等待
  后台任务最多 3 秒，随后取消剩余任务并正常退出。

- **AC20：错误隔离与日志**  
  条件、模板及各类动作故障不会中断 Agent 主流程，也不会递归触发 `agent.error`。日志
  能通过事件名、规则 ID、动作类型和结果定位执行情况，并对可能较大的内容进行限制。

- **AC21：配置约束**  
  权限决定用于非 `tool.before_execute` 事件、权限动作异步执行、System Reminder 异步
  执行或用于 `session.end` 等非法组合，均只跳过对应规则并显示准确诊断。

- **AC22：功能实验与回归**  
  通过代表性单元测试、集成测试和至少一个真实终端端到端场景，验证 Hook 生命周期触发、
  `allow`/`ask`/`deny`、单次审批、拒绝原因回填、System Reminder 注入以及
  禁用规则不触发以及 `once: true && executed: true` 后不再触发。现有权限、工具循环、
  上下文和会话核心测试没有回归。不要求压力、性能、长期稳定性、复杂故障注入或多平台
  验收。
