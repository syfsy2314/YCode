# YCode Agent Skills Spec

> 状态：待批准

## 背景

YCode 已具备 Agent 循环、工具调用、权限控制、项目上下文、会话持久化、上下文压缩、
MCP 扩展和统一 Slash Command 框架，但尚不支持把可复用的专业流程作为独立能力包交给
Agent 按需使用。

当前需要重复向模型描述代码审查、提交、测试等操作流程。若把所有流程长期放入系统
上下文，会持续占用 Token 并降低模型选择指令的准确性；若为每种流程编写专用内部命令，
又会使扩展能力依赖 YCode 代码修改。

本功能引入与 Anthropic Agent Skills 格式兼容的项目 Skill。Skill 以标准 `SKILL.md`
和随附资源描述能力，YCode 在启动时只公开名称和说明，在实际使用时才加载完整指令。
Skill 可以在主会话内持续工作，也可以在隔离上下文中执行并只返回最终交接结果。

同时，Skill 需要与现有命令、工具、权限、上下文和会话边界协同，并支持从用户提供的
HTTPS ZIP 地址安全安装到当前项目。

## 目标

- 支持发现、校验和运行项目目录中的标准 Agent Skill。
- 采用两级加载，启动时仅提供名称与说明，激活时加载完整 `SKILL.md`。
- 支持 Agent 根据任务自动调用 Skill，以及用户通过 `/<skill-name>` 显式调用。
- 支持共享和隔离两种执行模式，以及隔离模式的摘要、最近 N 个完整回合和无历史三种
  上下文策略。
- 让共享 Skill 的指令按会话持续生效，并支持多个共享 Skill 同时激活。
- 分离工具可见白名单和任务级预批准工具，同时保持现有模式、权限和执行器安全边界。
- 支持 Skill 嵌套调用，并限制循环和最大深度。
- 提供 Skill 状态查看、详情、停用、重新扫描和对话清空能力。
- 支持 Agent 通过内置安装工具，从公开 HTTPS ZIP 安全安装单个标准 Skill。
- 支持调用时重新读取源文件，并在显式重新扫描后更新目录、状态和 Slash Command。
- 以普通外部 Skill 形式提供 `commit`、`review`、`test` 三个生产力样板，不为它们
  编写专用内部流程。

## 功能需求

### F1：项目级发现与标准目录

YCode 只从当前项目根目录的 `.ycode/skills/` 发现 Skill。每个 Skill 必须使用：

```text
.ycode/skills/<name>/SKILL.md
```

不支持松散的单文件 Skill。`name` 必须与父目录一致，并满足 Anthropic Agent Skills
的名称约束。

### F2：标准元数据与 YCode 扩展

`SKILL.md` 使用 YAML frontmatter 和 Markdown 正文。

支持标准字段：

- `name`
- `description`
- `license`
- `compatibility`
- `metadata`
- `allowed-tools`

YCode 扩展通过 `metadata` 中的字符串字段表达：

- `ycode-visible-tools`
- `ycode-execution-mode`
- `ycode-model`
- `ycode-context`
- `ycode-recent-turns`
- `ycode-argument-hint`

没有 YCode 扩展字段的标准 Skill 默认使用共享模式、当前模型、当前会话上下文和当前
模式原本可见的工具，且不获得预批准权限。

### F3：扫描、校验与可用状态

YCode 启动时扫描全部项目 Skill，并校验目录、frontmatter、名称、执行配置、模型引用
和工具引用。

单个 Skill 无效时标记为“不可用”并记录明确原因，不阻止主程序启动。不可用 Skill
可以在 `/skills` 中查看，但不能激活或执行。

### F4：两级渐进加载

Skill 采用两级加载：

1. 启动时只向 Agent 提供所有可用 Skill 的名称和一句说明。
2. Skill 激活时加载完整 `SKILL.md` 正文。

随附资源不自动进入模型上下文。

### F5：共享模式

共享 Skill 激活后：

- 完整 SOP 作为会话级系统上下文持续存在；
- 后续 Agent 回合继续携带；
- 多个共享 Skill 可以同时激活，按名称确定性排列；
- 上下文压缩不得删除已激活 SOP；
- 直到显式停用、执行 `/clear` 或切换到没有该激活状态的会话时才移除。

### F6：隔离模式

隔离 Skill 在临时独立 Agent 上下文中执行，完整 SOP 和工具状态不进入主会话。

隔离 Skill 必须声明以下上下文策略之一：

- `summary`：携带主会话现有摘要和全部已提交历史生成的最新摘要；
- `recent`：携带最近 N 个完整用户回合；
- `none`：不携带先前主会话历史。

当前触发 Skill 的用户任务始终原样传入。`recent` 不得截断工具调用与工具结果配对。

隔离执行结束后，只把最终交接结果写入主会话；Thinking、工具调用、工具结果和中间
消息不回流。隔离历史不单独持久化，也不能通过 `/resume` 恢复。已经发生的工作区修改
不自动回滚。

### F7：隔离模型选择

共享 Skill 始终使用当前会话模型。

隔离 Skill 可以通过 `ycode-model` 引用已有 Anthropic Provider 配置；未声明时继承
当前活动配置。Skill 不得声明 API Key、`base_url` 或创建新的 Provider。

共享模式声明模型、隔离模式缺少上下文策略、`recent` 缺少合法回合数等无效组合会使
Skill 不可用。

### F8：自动与显式调用

系统提供始终可发现的 `load_skill` 工具，Agent 可以根据目录中的名称和说明自动调用
Skill。

每个可用 Skill 自动注册 `/<skill-name>` Slash Command。只有用户提交命令后才激活并
执行；输入、补全和查看帮助不会激活。

显式调用和自动调用都在实际执行前重新读取并校验当前 `SKILL.md`。读取或校验失败时
不激活、不调用 Skill、不写入任务历史。

### F9：Slash Command 参数

`/<skill-name> <参数>` 的参数作为本次任务输入单独发送，不替换或修改持久 SOP。

参数保持原始大小写、内部空格和内容。无参数时明确表示未提供调用参数。本期不支持
`$ARGUMENTS`、`$0` 等正文替换语法。

终端显示原始 Slash Command，模型和会话存档记录展开后的 Skill 任务，不重复保存
原命令。

### F10：工具可见性

`metadata.ycode-visible-tools` 表示模型可见工具白名单，只能收窄工具集合，不能授予
权限。

多个已激活共享 Skill 的可见白名单取并集。未声明该字段时继承当前模式原本可见的工具。

支持 YCode 原生工具名称和以下常见名称映射：

- `Read` → `read_file`
- `Write` → `write_file`
- `Edit` → `edit_file`
- `Bash`、`PowerShell` → `run_command`
- `Glob` → `glob`
- `Grep` → `grep`
- `ToolSearch` → `tool_search`

本期不支持 `Bash(git:*)` 等参数级表达式。

### F11：任务级预批准

标准 `allowed-tools` 表示本次 Skill 任务内免人工审批的工具集合，必须属于当前可见工具
集合。

预批准只由本次实际调用的 Skill 及其嵌套 Skill 贡献，并在任务完成、失败或取消后立即
清除。以前激活但本次没有再次调用的共享 Skill 不贡献预批准权限。

预批准不能绕过安全配置拒绝、plan-only、工作区边界和执行器安全检查。

### F12：自动激活审批

用户显式提交 `/<skill-name>` 时，视为主动授权该 Skill 本任务声明的 `allowed-tools`。

Agent 自动调用或嵌套调用带有 `allowed-tools` 的 Skill 时，必须先向用户展示 Skill
名称和预批准工具并获得确认。用户拒绝后不激活、不授予权限，但父 Agent 任务可以继续。

没有 `allowed-tools` 的 Skill 可以自动激活，不增加额外审批。

### F13：任务模式继承

Skill 始终继承当前任务模式：

- `load_skill` 在 plan-only 中仍可使用；
- 共享和隔离 Skill 在 plan-only 中只能使用读取类工具；
- Skill 白名单和预批准不能引入写工具；
- 显式 Skill 命令不会自动切换到 agent 模式；
- `install_skill` 在 plan-only 中不可用。

### F14：嵌套调用

Skill 可以通过 `load_skill` 调用其他 Skill。

- 已激活共享 Skill 再次加载时不重复注入 SOP；
- 禁止循环调用；
- 最大嵌套深度为 3；
- 每层独立应用执行模式、上下文策略、可见工具和预批准审批；
- 嵌套隔离 Skill 只向直接父 Agent 返回最终交接结果。

### F15：随附资源

Skill 可以包含 `scripts/`、`references/`、`assets/` 及其他标准随附文件。

这些文件不自动加载。Agent 根据 SOP 使用现有文件工具按需读取资源，并使用现有命令
工具执行脚本。资源和脚本访问继续服从 Skill 工具配置、权限审批和工作区边界。

本期不把脚本自动注册为结构化工具。

### F16：Skill 管理命令

系统提供：

```text
/skills
/skills show <name>
/skills deactivate <name>
/skills reload
```

行为包括：

- 列出 Skill 的来源、可用状态和激活状态；
- 查看元数据、模式、模型、上下文策略和不可用原因；
- 停用共享 Skill，并从下一回合移除其 SOP 和工具影响；
- 强制重新扫描项目 Skill。

这些命令不调用普通 Agent，也不进入对话历史。

### F17：热更新与重新扫描

提交 `/<skill-name>` 或调用 `load_skill` 时重新读取该 Skill。成功后替换激活快照；失败
时保留此前有效快照。

新增、删除或重命名 Skill 通过 `/skills reload` 生效。重新扫描成功后更新目录、状态、
帮助、补全和 Slash Command。

单个 Skill 在扫描后删除或失效时标记为不可用，并自动停用；扫描过程自身失败时保留
原目录和激活状态，不提交半成品更新。

### F18：对话清空

新增正式内置命令 `/clear`。执行后：

- 开始新的空会话；
- 保留旧会话存档并允许以后恢复；
- 清空历史、上下文摘要和已激活 Skill；
- 清除临时权限授权；
- 模式重置为 agent；
- 保留项目 Skill 目录、MCP 连接、项目记忆和当前权限配置模式；
- 不调用模型，也不把命令写入历史。

### F19：会话恢复

共享 Skill 的激活和停用状态随会话持久化。

恢复会话时重新读取当前磁盘上的 Skill：

- 有效时恢复激活；
- 已删除、改名或不可用时跳过并显示告警；
- 不保存或恢复旧 SOP 副本；
- 不恢复任务级预批准；
- 隔离 Skill 不保存激活状态。

### F20：远程安装工具

系统提供模型可调用的 `install_skill` 工具。工具接收公开 HTTPS ZIP URL，并始终要求
人工审批。

ZIP 必须：

- 下载体积和解压后总量均不超过 30 MB；
- 只包含一个顶层 Skill 目录；
- 顶层目录名与 `SKILL.md` 的 `name` 一致；
- 不包含绝对路径、目录越界、符号链接或 Junction。

安装过程先在临时区域完整下载、解压和校验，再原子写入
`.ycode/skills/<name>/`。同名 Skill 已存在时拒绝覆盖。

安装成功后立即刷新目录和 Slash Command，但不自动激活或执行 Skill。合法包若因模型、
工具或环境依赖缺失而当前不可运行，仍完成安装并标记为不可用。

### F21：安装范围

`install_skill` 只支持公开 HTTPS ZIP：

- 不支持认证 Header、URL 内凭据或私有仓库认证；
- 不支持 Git clone；
- 不支持市场查询、版本选择、更新或覆盖安装；
- 安装失败不得留下半安装目录。

### F22：名称与命令冲突

内置 Slash Command 名称始终优先。Skill 与内置命令冲突时标记为不可用。

多个项目 Skill 规范化后重名时，两者都不可用，不按扫描顺序覆盖。正常无冲突 Skill
的命令顺序、帮助和补全保持确定性。

### F23：示例 Skill

项目以普通外部 Skill 形式提供：

```text
.ycode/skills/commit/SKILL.md
.ycode/skills/review/SKILL.md
.ycode/skills/test/SKILL.md
```

它们不使用专用内部代码：

- `commit` 使用共享模式；
- `review` 使用隔离模式并携带最近 5 个完整用户回合；
- `test` 使用隔离模式且不携带历史。

删除目录后，对应 Skill 和 Slash Command 按普通扫描规则消失。

## 非功能需求

- **N1：Anthropic 范围**  
  本功能只面向 Anthropic Agent 路径。核心 Skill 模型保持供应商无关边界，但不新增或
  修改 OpenAI 配置、Provider、协议转换、执行流程或测试场景。

- **N2：标准兼容性**  
  不包含 YCode 扩展字段的合法 Anthropic Agent Skill 必须能够直接发现、安装和运行。
  YCode 扩展只能位于标准允许的 `metadata` 中，不能破坏 Skill 在其他兼容 Agent 中的
  基本可读性。

- **N3：确定性**  
  相同项目内容必须产生稳定的 Skill 目录顺序、激活顺序、工具集合、命令帮助和补全
  结果。不得依赖文件系统返回顺序处理冲突或选择 Skill。

- **N4：最小上下文成本**  
  未激活 Skill 只贡献名称和说明。Skill 正文、随附资源和隔离历史不得无条件进入主
  会话。共享 Skill 停用后必须从后续请求中移除。

- **N5：权限不可绕过**  
  Skill 指令、可见工具和预批准均不能绕过 plan-only、安全配置、工作区边界、命令安全
  检查或执行器限制。自动激活不能静默获得新的免审批能力。

- **N6：远程内容安全**  
  下载、错误、状态和日志不得泄露凭据、认证信息、环境变量或无关机器信息。ZIP 解压
  必须防止路径穿越、链接越界、覆盖现有文件和压缩炸弹式超限写入。

- **N7：事务与失败隔离**  
  扫描、重新加载、安装、激活、停用和会话恢复不得提交半完成状态。单个 Skill 无效、
  依赖缺失或恢复失败不得破坏其他 Skill、当前会话或 YCode 主流程。

- **N8：取消与资源释放**  
  Skill 安装、隔离执行、上下文摘要和工具调用必须响应用户取消。取消后关闭相关网络
  响应、模型流和子任务，不残留临时安装文件或活动预批准。

- **N9：会话一致性**  
  Skill 状态写入会话时继续遵守现有“先落盘、后提交内存”的事务边界。存储失败时不得
  只更新内存状态。恢复、压缩和 `/clear` 后的 Skill 状态必须与可观察会话一致。

- **N10：热更新一致性**  
  已激活 Skill 使用明确快照；磁盘变化不能在回合中途改变当前请求。调用时重读和显式
  reload 只能在完整校验后替换状态。

- **N11：交互兼容性**  
  新增动态 Skill 命令后，现有 `/help`、Tab 补全、未知命令处理、输入空闲限制、取消和
  终端布局不得回归。动态命令不能覆盖内置命令。

- **N12：现有能力不回归**  
  Anthropic 流式输出、Thinking、Agent 工具循环、MCP、权限审批、plan-only、上下文
  压缩、会话恢复、项目记忆和退出整理的既有顺序与安全保证不得削弱。

- **N13：可诊断性**  
  `/skills`、详情、安装结果、启动告警和恢复告警必须使用安全、可操作的文字区分：可用、
  已激活、不可用、安装失败、安装成功但不可用，以及具体原因。

- **N14：可测试性**  
  标准解析、状态转换、工具权限、上下文策略、嵌套、命令刷新、ZIP 安装和会话恢复必须
  能通过本地替身与临时目录验证。自动化测试不得调用真实付费模型或不受控公网服务。

- **N15：实现复杂度约束**  
  只实现本 Spec 明确要求的 Skill 行为，不引入市场、版本解析、插件运行时、自定义结构化
  工具协议或未确认的扩展机制。

## 不做的事

- 不适配 OpenAI 路径；OpenAI Skill 支持留到项目整体功能完成后的独立 Spec。
- 不扫描或安装用户级 Skill；`%USERPROFILE%/.ycode/skills/` 列为待开发内容。
- 不扫描父目录、子项目或嵌套 `.ycode/skills/`；本期只使用当前项目根目录。
- 不支持 `.ycode/skills/<name>.md` 等松散单文件格式。
- 不支持一个 ZIP 安装多个 Skill，也不支持 `SKILL.md` 直接位于 ZIP 根目录。
- 不提供 Skill 市场、搜索、发布、推荐、签名、版本管理、自动更新或覆盖安装。
- 不支持私有 URL、认证 Header、URL 凭据、Git 仓库克隆或本地归档安装。
- 不提供 `/skills uninstall`；用户可以删除对应项目目录后执行 `/skills reload`。
- 不自动监视文件系统变化；新增、删除和重命名通过 reload 生效，已有 Skill 在调用时
  重读。
- 不支持 `$ARGUMENTS`、`$0`、动态 Shell 注入或其他 Claude Code 专属正文扩展。
- 不支持 `Bash(git:*)` 等参数级工具授权表达式。
- 不允许 Skill 定义 API Key、`base_url`、新 Provider 或新的权限模式。
- 不实现 Skill 专属结构化工具、私有子进程工具协议、Skill 内 MCP Server 或插件运行时。
- 不把 `scripts/` 自动注册成模型工具；脚本仅通过现有命令工具按 SOP 执行。
- 不为 `commit`、`review`、`test` 编写专用内部处理逻辑。
- 不持久化或单独恢复隔离 Skill 的内部对话。
- 不为取消或失败的 Skill 自动回滚已经发生的工作区修改。
- 不支持后台 Skill、定时执行、并行子代理、团队 Agent 或隔离任务列表。
- 不提供图形化 Skill 编辑器、生成器或交互式安装市场。
- 不做压力测试、性能基准、长时间稳定性、复杂并发、故障注入、全面安全审计、恶意公网
  样本、多平台矩阵或真实付费 API 自动化测试。

## 验收标准

- **AC1（F1、F2）标准格式与默认行为**  
  在 `.ycode/skills/<name>/SKILL.md` 放入只包含标准 `name` 和 `description` 的合法 Skill
  后，YCode 能发现并以共享模式运行；目录名不匹配、非法名称、缺少必填字段或无效
  frontmatter 会显示明确不可用原因。

- **AC2（F2、F7）YCode 扩展配置**  
  `metadata` 中的共享/隔离模式、模型、上下文策略、最近回合数、可见工具和参数提示能够
  正确生效；无效字段组合不会自行采用猜测值，而是将 Skill 标记为不可用。

- **AC3（F3、F22）扫描与故障隔离**  
  同时存在合法、损坏、工具缺失、模型缺失和命令冲突的 Skill 时，合法 Skill 正常可用，
  其他 Skill 显示各自原因，YCode 仍能启动和进行普通对话。

- **AC4（F4）两级加载**  
  启动后的模型请求只包含 Skill 名称和说明，不包含未激活 Skill 的正文及资源；激活后
  下一模型轮次能看到完整 `SKILL.md` 正文。

- **AC5（F5）共享 Skill 生命周期**  
  激活两个共享 Skill 后，后续回合按稳定顺序同时携带两份 SOP；上下文压缩后仍然存在；
  停用其中一个后，下一回合只保留另一个。

- **AC6（F6、F7）隔离执行与上下文策略**  
  分别运行 `summary`、`recent` 和 `none` 隔离 Skill，可以观察到隔离 Agent 收到对应
  上下文；`recent` 以完整用户回合为单位且不破坏工具配对；主会话只收到最终交接结果。

- **AC7（F6）隔离失败与取消**  
  隔离任务成功、失败和取消时，内部 Thinking、工具历史和中间消息均不进入主历史，
  也不生成可恢复子会话；已经发生的工作区修改不自动回滚。

- **AC8（F8、F9）自动与显式调用**  
  普通任务可以触发 Agent 调用 `load_skill`；提交 `/<name> 原始参数` 可以激活并立即
  执行。仅输入、补全或查看帮助不会激活。参数作为独立任务内容传入，不修改持久 SOP。

- **AC9（F8、F17）调用时热更新**  
  修改已存在 Skill 的正文后再次调用，可以观察到新内容生效；无效修改不会替换此前
  有效激活快照。新增、删除或重命名只有在 `/skills reload` 后更新命令目录。

- **AC10（F10）工具可见白名单**  
  单个和多个共享 Skill 激活时，模型工具列表分别等于声明白名单及其并集，并继续受当前
  模式限制。标准名称和 YCode 原生名称映射到相同工具；未知名称使 Skill 不可用。

- **AC11（F11、F12）预批准与自动激活审批**  
  显式 Skill 任务中，`allowed-tools` 免除本任务人工审批；任务结束后授权消失。Agent
  自动或嵌套加载带预批准工具的 Skill 时先请求确认，拒绝后不授予权限且父任务可以继续。

- **AC12（F11、F13）底层权限优先**  
  预批准工具仍不能突破安全拒绝、工作区边界或 plan-only。plan-only 中加载和执行 Skill
  时只暴露读取工具，`install_skill` 和写操作不可用，Skill 调用不会自动切换模式。

- **AC13（F14）嵌套调用**  
  两层和三层 Skill 嵌套能够完成并把结果逐层返回；循环调用和第四层调用返回稳定错误；
  重复加载已激活共享 Skill 不重复注入 SOP。

- **AC14（F15）随附资源**  
  Skill 激活时不会自动注入 `scripts/`、`references/` 或 `assets/`；SOP 明确引用资源后，
  Agent 可以通过现有文件和命令工具按需访问，并经过正常权限流程。

- **AC15（F16、F18）管理与清空命令**  
  `/skills`、详情、停用和 reload 的输出与实际状态一致，且不调用普通 Agent 或写入历史。
  `/clear` 创建空会话、清除摘要和共享 Skill、重置模式及临时授权，同时旧会话仍可恢复。

- **AC16（F19）会话恢复**  
  恢复包含共享 Skill 状态的会话时，有效 Skill 使用当前磁盘内容重新激活；删除或不可用
  Skill 产生告警但不阻止恢复；任务级预批准和隔离 Skill 状态不恢复。

- **AC17（F20、F21）URL 安装成功**  
  Agent 调用 `install_skill` 时显示 HTTPS URL 并请求审批。批准后，一个符合严格顶层目录
  规则且不超过 30 MB 的 ZIP 被原子安装到项目目录，立即出现在 `/skills`、帮助和补全中，
  但不会自动执行。

- **AC18（F20、F21）URL 安装失败与不可用状态**  
  HTTP 失败、超限、损坏 ZIP、多个顶层目录、名称不匹配、路径越界、链接或同名目录不会
  留下半安装内容。结构合法但依赖缺失的 Skill 完成安装，并显示“已安装但不可用”及原因。

- **AC19（F22）动态命令冲突**  
  Skill 与内置命令冲突时内置命令行为不变；两个规范化名称冲突时不会随机覆盖。reload
  失败保留此前完整命令目录和激活状态。

- **AC20（F23）普通示例 Skill**  
  `/commit` 通过共享模式执行；`/review` 在携带最近 5 个完整回合的隔离上下文中执行；
  `/test` 在无历史隔离上下文中执行。删除对应目录并 reload 后，命令按普通规则消失，
  证明没有专用内部流程。

- **AC21（N11、N12）回归与真实交互**  
  现有 Anthropic 流式对话、Thinking、工具循环、MCP、审批、plan-only、压缩、恢复和记忆
  测试通过；在真实 PTY 中完成 Skill 安装、显式调用、自动调用、停用、reload、`/clear`
  和安全退出流程。

- **AC22（N14、N15）验证范围**  
  使用本地替身、临时目录和受控本地下载服务完成核心功能验证，不调用真实付费模型或
  不受控公网服务，也不扩展到压力、性能、长期稳定性、故障注入或多平台验证。
