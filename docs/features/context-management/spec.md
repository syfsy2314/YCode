# YCode 上下文管理 Spec

> 状态：已批准

## 背景

YCode 当前会在进程内保存所有已完成的对话消息，并在每次 Anthropic 请求及同一
Agent 回合的后续工具轮次中重新发送完整历史。随着会话增长，工具结果、工具元信息、
助手回复和工具调用过程会持续占用上下文，其中工具结果通常是主要消耗来源。

当前系统缺少请求前的上下文预算检查、超大工具结果外置、历史摘要、手动压缩和连续
失败熔断。当输入逼近模型上下文窗口时，请求可能失败，或者模型因有效上下文不足而
降低任务完成质量。

## 目标

- 在每次 Anthropic 主模型请求前，依次执行轻量工具结果控制和整体历史压缩。
- 将超限工具结果安全写入工作区临时存储，在对话中只保留可读取的预览与引用。
- 当完整请求逼近上下文窗口时，通过无工具的专用 LLM 请求生成结构化摘要，替换旧
  历史。
- 自动压缩时原样保留当前活动回合的最新用户消息；摘要中的重要用户内容尽量保留
  原文，并区分原文与概述。
- 在压缩后提供明确的记忆与边界提醒，要求模型在需要精确信息时重新读取文件或工具
  结果，禁止依据摘要臆造代码。
- 支持 `/compact` 手动压缩、摘要失败计数和自动压缩熔断。
- 保持现有整轮历史事务语义，失败或取消的 Agent 回合不提交临时摘要及本轮消息。
- 首版只完成 Anthropic 功能路径，并以核心功能测试为主，不扩展复杂的生产级验证。

## 功能需求

### 请求前处理

- **F1：Anthropic 主请求预检**
  每次 Anthropic 主模型请求前，系统必须依次执行两层处理：先控制工具结果大小，再
  检查完整请求是否需要摘要。内部摘要请求使用已完成第一层处理的只读 transcript，
  并跳过第二层，避免递归摘要。

- **F2：完整请求计量**
  整体上下文计量必须覆盖 System Prompt、动态系统补充、工具 Schema、对话消息及其
  结构开销，不能只计算会话历史。系统使用本地保守估算，并结合上一次 Anthropic
  响应返回的实际输入 Token 数校准，二者取较大值；不得为每次请求额外调用 Token
  Count API。

### 工具结果控制

- **F3：统一计量口径**
  所有工具结果均适用相同规则，包括内建工具、MCP 工具、成功结果、错误结果和权限
  拒绝结果。大小按密钥脱敏后、最终提供给模型的完整序列化结果计算，现有正文与元
  信息中的重复数据不作额外消除。1 KiB 按 1024 字节计算。

- **F4：单结果限制**
  单个工具结果超过 50 KiB 时，系统必须将脱敏后的完整安全结果写入磁盘，并用稳定
  的 JSON 引用替换历史中的原结果。

- **F5：单消息聚合限制**
  一条消息内全部工具结果的最终大小超过 200 KiB 时，系统必须先完成所有单结果超限
  处理，再从仍保留完整正文的结果中按大小降序依次存盘，直到消息不超过上限。

- **F6：预览与最小引用**
  每个存盘结果默认保留不超过 4 KiB 的预览，约由开头 3 KiB 和结尾 1 KiB 组成。
  预览和引用自身也计入 200 KiB 聚合限制；如果所有完整结果都已存盘后仍超限，系统
  必须继续缩短预览，必要时只保留工具名、调用 ID、路径、原始字节数和 SHA-256。

- **F7：存盘结构与可读性**
  工具结果存放在当前工作区的会话级上下文目录中。每个结果必须提供 manifest；正文
  过大时按不超过 50 KiB 的连续分片保存，保证原始安全内容可以无损重组，并可通过
  模型已有的工作区文件读取能力重新读取。对话中的 JSON 引用必须包含存盘标记、工具
  名、调用 ID、manifest 相对路径、原始字节数、SHA-256 和预览。

- **F8：密钥与写盘失败**
  写盘和预览生成前必须使用当前已知秘密进行脱敏。写盘失败时不得截断后继续，也不得
  丢弃完整结果；当前 Agent 回合以 `context_storage_error` 结束，且不提交本轮历史。

- **F9：存盘幂等与生命周期**
  工具批次完成后、进入后续模型历史前执行存盘；每次主请求前再次进行幂等检查。正常
  关闭时只删除本会话目录。每个目录记录会话进程及启动信息；启动时只清理进程已不
  存在且遗留超过 24 小时的目录，不能影响其他正在运行的 YCode 会话。上下文目录必须
  被 Git 忽略。

### 自动摘要

- **F10：上下文窗口配置与预算**
  YAML 顶层提供 `context_window_tokens`，默认值为 200,000。该值必须是大于 33,000
  的严格整数。摘要最大总输出为 20,000 Token，估算安全余量为 13,000 Token，
  因此：
  - 自动摘要阈值为 `context_window_tokens - 20,000 - 13,000`；
  - 摘要失败后原请求可继续发送的上限为 `context_window_tokens - 20,000`。

  默认配置下二者分别为 167,000 和 180,000 Token。

- **F11：自动摘要范围**
  完整请求预估输入超过自动摘要阈值时，系统必须尝试全量摘要。摘要覆盖已有会话记忆、
  旧历史以及当前任务中已经完成的过程，但当前活动回合最新一条真实用户消息必须原样
  保留在摘要之外。若超限主要来自不可压缩的固定上下文或最新用户消息，系统不调用
  无意义的摘要请求，而以 `context_uncompressible` 结束当前操作。

- **F12：只读摘要输入**
  待压缩历史必须渲染成确定性的只读 transcript，标注消息 ID、角色、助手文本、工具
  名称、工具参数、工具结果和存盘引用。Transcript 中的内容必须被明确声明为待总结
  数据而非指令。所有 Thinking 文本、Thinking signature 和 Redacted Thinking 数据
  均不得进入摘要输入。

- **F13：专用摘要请求**
  摘要请求只包含旧记忆和待压缩 transcript，使用独立的摘要 System Prompt；不得携带
  主 Agent Prompt、环境补充、权限状态、工具目录或工具 Schema。请求不得提供任何
  工具，并必须强制关闭 Anthropic 原生 Thinking。摘要 Prompt 的开头和结尾都必须
  明确禁止调用工具；模型仍返回工具调用时，摘要失败。

- **F14：草稿与正式摘要**
  摘要模型在同一次响应中先输出 `<analysis_draft>`，再输出 `<summary>`；20,000 Token
  是两部分合计的最大输出。草稿必须简洁，解析完成后立即丢弃，不得写入会话记忆或
  对话历史。

- **F15：正式摘要结构**
  `<summary>` 内必须按下列顺序包含九个固定中文 Markdown 标题：
  1. 主要请求
  2. 关键概念
  3. 文件代码
  4. 错误修复
  5. 解决过程
  6. 用户原话
  7. 待办
  8. 当前工作
  9. 下一步

  标题必须齐全且顺序固定，空部分写“无”。说明文字跟随当前对话的主要语言，用户
  原话保持原语言。

- **F16：用户原话校验**
  “用户原话”中的内容必须明确标记为“原文”或“概述”。程序必须验证所有标记为“原文”
  的文本确实存在于对应用户消息中；验证失败则摘要失败。模型没有把握逐字保留时必须
  使用“概述”，不得把转述冒充原文。

- **F17：摘要替换与边界提醒**
  摘要成功后，结构化摘要作为唯一一份会话级记忆，独立边界提醒作为会话级系统提醒。
  后续再次压缩时，旧摘要与新增历史共同生成一份新摘要，并原子替换旧摘要，不得堆叠
  多份摘要。边界提醒必须说明摘要不是代码事实；需要精确文件、接口或错误细节时必须
  重新读取文件或存盘工具结果，禁止依据摘要臆造内容。

- **F18：摘要成功条件**
  只有响应正常结束、没有工具调用、草稿与摘要边界可解析、九部分结构校验通过、所有
  原文校验通过，且压缩后的完整请求不超过自动摘要阈值时，摘要才算成功。

### 事务、命令与熔断

- **F19：自动压缩事务**
  自动摘要及压缩后的工作历史属于当前 Agent 回合的临时状态。只有整个回合正常完成时
  才提交；Provider 失败、用户取消或达到 Agent 轮数上限时，摘要与本轮历史一起回滚。
  已经安全写出的工具结果文件保留到会话关闭。

- **F20：手动压缩**
  `/compact` 是不进入对话历史的本地命令，无论当前 Token 数是否达到自动阈值，都尝试
  压缩全部已提交历史；手动压缩不额外保留最近用户消息。成功后显示压缩前后的预估
  Token。没有可压缩历史时返回 `compact_not_needed`，不调用 LLM，也不计失败。

- **F21：摘要失败与继续请求**
  每次主请求预检最多自动尝试一次摘要，不得在同一次预检中循环修复或重试。摘要失败
  后，若原请求预估输入未超过继续发送上限，则允许发送原主请求；超过上限则停止并
  提示用户执行 `/compact`。

- **F22：连续失败熔断**
  自动与手动摘要共用连续失败计数。Provider 异常、异常停止、工具调用、格式或原文
  校验失败，以及摘要后仍超阈值都计为失败；没有可压缩历史不计失败。连续失败 3 次后，
  本会话停止自动摘要。熔断后 `/compact` 仍可执行；任意摘要成功都会清零计数并恢复
  自动摘要。

- **F23：终端反馈**
  工具结果自动存盘不额外刷屏。自动摘要成功时显示一次压缩前后预估 Token；失败时
  显示连续失败次数；进入熔断时明确提示用户可使用 `/compact`。

## 非功能需求

- **N1：Provider 范围**
  首版只以 Anthropic 作为实际配置、请求、摘要和交互验证目标。公共上下文管理职责应
  保持可扩展边界，但不得同步实现或测试 OpenAI 适配。

- **N2：请求开销**
  未达到自动摘要阈值时，请求前处理必须保持本地、轻量，不增加 Token Count 网络调用
  或额外 LLM 请求。只有达到阈值或用户执行 `/compact` 时才允许发起摘要请求。

- **N3：数据完整性**
  超限工具结果不得被静默丢弃。存盘内容、manifest、哈希和历史引用必须保持一致；
  写盘或摘要任一步失败时，不能留下已提交但无法读取的会话状态。

- **N4：安全性**
  已知 API Key、MCP Header 和环境秘密不得出现在存盘正文、预览、终端提示或错误信息
  中。上下文文件只能写入当前工作区规定的会话目录，不能通过未校验路径写到工作区外。

- **N5：幂等性与并发隔离**
  同一个已存盘工具结果在后续请求预检中不得重复写盘。多个 YCode 进程同时运行时，
  会话目录和清理行为必须相互隔离。

- **N6：事务一致性**
  上下文压缩不得破坏现有整轮提交语义。模型请求、摘要状态、对话历史和终态事件之间
  不能出现部分提交。

- **N7：确定性与可诊断性**
  相同消息和配置应产生稳定的大小判断、transcript、摘要结构校验及引用格式。失败必须
  返回稳定错误码和不包含敏感正文的用户可读原因。

- **N8：正常路径兼容**
  未触发工具结果存盘或整体摘要时，现有 Anthropic 对话、工具调用、权限审批、MCP、
  Plan 模式和终端流式展示行为不得改变。

- **N9：功能性验证范围**
  验证以核心功能为主，包括阈值判断、存盘引用、摘要结构、事务、命令和熔断的单元或
  功能测试，以及一个简洁的终端交互流程。仍执行项目规定的格式、静态检查、完整测试
  和编译检查，但不新增以下复杂生产级验证：
  - 压力测试或性能基准；
  - 长时间稳定性运行；
  - 大规模并发或进程竞争测试；
  - 多操作系统兼容矩阵；
  - 真实断电、磁盘损坏或系统崩溃注入；
  - 真实 Anthropic 账号的费用型大上下文测试。

- **N10：测试安全**
  自动化测试使用虚拟 Provider、本地模拟响应和占位秘密，不连接真实模型服务，不读取
  或修改用户级配置，也不在测试输出中保存真实敏感数据。

## 不做的事

- 不实现或扩展 OpenAI 的上下文管理、配置、命令行为、Provider 适配、测试夹具或验收
  场景；OpenAI 统一适配留待项目整体功能完成后的独立 Spec。
- 不删除或重写现有 OpenAI 功能；若后续技术设计发现无法避免影响，必须停止并重新向
  用户确认。
- 不实现跨进程对话恢复、摘要持久化、会话数据库或历史会话浏览。
- 不把工具结果存盘机制扩展到用户消息、助手普通文本、Thinking 或 System Prompt。
- 不摘要、截断或外置当前活动回合的最新用户消息。
- 不缩减 System Prompt、动态系统补充或工具 Schema 来规避上下文限制。
- 不调用 Anthropic Token Count API，也不追求与供应商 tokenizer 完全一致的本地精确
  计数。
- 不实现分段摘要、树形摘要或摘要请求自身超出上下文窗口时的应急压缩。
- 不在单次预检中自动重试摘要、二次调用 LLM 修复格式，或让摘要请求再次触发自动摘要。
- 不支持 `/compact` 参数、自定义摘要重点或用户自定义摘要 Prompt。
- 不开放摘要输出、安全余量、工具结果大小、预览大小、熔断次数等高级配置；首版只开放
  顶层 `context_window_tokens`。
- 不消除工具结果正文与 metadata 中的现有重复数据；阈值按当前最终序列化结果计算。
- 不新增专用上下文文件读取工具；存盘结果使用现有工作区文件读取能力访问。
- 不保存未经已知秘密脱敏的工具结果，也不实现本地加密存储和密钥管理。
- 不为异常遗留目录实现复杂的跨机器锁、分布式租约或系统级清理服务。
- 不改变现有 Anthropic 主请求的最大输出 Token 设置、工具权限规则、MCP 延迟加载策略
  或 Agent 最大轮数。
- 不开展压力、性能基准、长时间运行、大规模多进程、多平台矩阵、真实故障注入或真实
  付费大上下文验证。

## 验收标准

以下验收以虚拟 Provider、临时工作区和本地功能测试为主，不要求真实大上下文或生产级
故障环境。

- **AC1（F1、F13）——处理顺序与递归隔离**
  构造一个同时包含超限工具结果且整体超过摘要阈值的主请求，观察到工具结果先被存盘，
  随后才调用摘要模型；摘要请求不提供工具、不执行第二层自动摘要，且整个流程只产生
  一次摘要调用。

- **AC2（F2、F10）——完整请求估算**
  分别增加 System Prompt、动态补充、工具 Schema 和历史消息，预估输入量均相应增长；
  存在上一请求实际输入量时，最终估算不会低于本地估算或校准结果中的较大值，也不会
  调用 Token Count API。

- **AC3（F3、F4、F6）——单结果阈值**
  所有来源及成功/错误状态的工具结果均使用相同规则。最终序列化大小等于 50 KiB 时
  保留完整结果，超过 50 KiB 时改为稳定 JSON 引用；默认预览不超过 4 KiB，并同时
  包含开头和结尾内容。

- **AC4（F5、F6）——聚合阈值**
  一条消息内多个结果合计不超过 200 KiB 时不做额外存盘；超过时，在处理单结果超限后
  按剩余结果大小降序依次存盘。引用和预览计入最终大小；必要时预览缩减为最小引用，
  并确保整条消息不超过 200 KiB。

- **AC5（F7、F9）——存盘完整性与幂等**
  外置结果生成可读取的 manifest 和连续正文分片，每个分片不超过 50 KiB；按 manifest
  顺序重组后与脱敏后的原始完整序列化结果一致，SHA-256 匹配。相同结果经过多次请求
  预检后不会产生重复文件。

- **AC6（F8、N4）——秘密脱敏**
  使用唯一秘密哨兵构造工具正文和 metadata，存盘文件、manifest、JSON 引用、预览、
  终端提示及错误信息中均不存在该哨兵，其他非敏感内容保持完整。

- **AC7（F8、F19）——写盘失败**
  模拟目录不可写或写入失败，当前回合以 `context_storage_error` 结束；模型不会收到截断
  结果，会话不提交本轮消息或临时摘要，之前已提交历史保持不变。

- **AC8（F9、N5）——会话目录清理**
  正常关闭只删除本会话目录。使用虚拟进程状态和时间构造活动目录、未满 24 小时的遗留
  目录及超过 24 小时的失效目录，启动清理只删除最后一种；上下文目录不会被 Git 跟踪。

- **AC9（F10）——配置与预算**
  缺省配置得到 200,000 Token 窗口、167,000 自动摘要阈值和 180,000 失败后继续上限。
  配置其他合法窗口时，两条边界按固定预留同步变化。布尔值、字符串、浮点数及不大于
  33,000 的值均被拒绝并给出字段定位。

- **AC10（F11、F18）——自动摘要范围**
  请求估算超过阈值时自动摘要旧记忆、旧历史和当前任务已完成过程，同时在压缩后请求中
  逐字保留最新真实用户消息。摘要后的完整请求不超过自动摘要阈值才算成功；固定上下文
  或最新用户消息导致无可压缩空间时返回 `context_uncompressible`，且不调用摘要模型。

- **AC11（F12、F13、F14）——摘要请求隔离**
  摘要模型只收到专用 System Prompt、旧记忆和只读 transcript；不包含主 Agent Prompt、
  环境、权限、工具目录、工具 Schema、Thinking、signature 或 redacted 数据。原生
  Thinking 被关闭，工具列表为空，Prompt 首尾均存在禁止工具调用要求。

- **AC12（F14、F15）——草稿与固定结构**
  合法响应按顺序包含 `<analysis_draft>` 和 `<summary>`；提交后的会话状态中不存在草稿。
  正式摘要恰好包含九个固定中文标题且顺序正确，空部分为“无”。缺少标签、标题缺失、
  顺序错误、异常停止或模型返回工具调用时，本次摘要失败且不会自动发起修复请求。

- **AC13（F16）——用户原话验证**
  “原文”条目与来源用户消息完全对应时摘要可通过；修改字词、标点或内容后校验失败。
  “概述”条目不要求逐字匹配，但不能被标记或展示为原文。用户原文保持原语言。

- **AC14（F17、F18）——滚动记忆与边界**
  第一次成功压缩后，请求中存在一份结构化记忆和一份独立边界提醒。新增历史再次压缩后，
  旧记忆被新记忆原子替换，会话中仍只有一份摘要；边界提醒明确要求重新读取精确资料并
  禁止根据摘要臆造代码。

- **AC15（F19、N6）——整轮事务**
  自动压缩后分别模拟正常完成、Provider 失败、用户取消和达到轮数上限；只有正常完成
  提交摘要及本轮消息，其他情况均恢复压缩前的已提交历史。

- **AC16（F20）——手动命令**
  在远低于自动阈值时执行 `/compact`，仍调用一次摘要并压缩全部已提交历史，不保留最近
  用户消息，命令本身不进入历史。空历史时返回 `compact_not_needed`，不调用模型、
  不增加失败次数。

- **AC17（F21、F22）——失败、硬上限与熔断**
  每次主请求预检最多调用一次摘要。摘要失败且原请求不超过继续上限时，主请求继续发送；
  超过上限时停止并提示 `/compact`。连续三次实际摘要失败后自动摘要熔断，之后不再自动
  调用；手动压缩仍可执行，成功后清零计数并恢复自动摘要。

- **AC18（F23）——终端反馈**
  工具结果自动存盘不会产生额外刷屏。自动摘要成功只显示一次压缩前后预估 Token；失败
  显示连续次数；第三次失败明确显示熔断状态和 `/compact` 提示。

- **AC19（N1、N8）——范围与现有行为**
  未达到任何阈值时，Anthropic 文本流、工具循环、权限审批、MCP、Plan 模式和历史提交
  行为与现状一致。功能不新增或修改 OpenAI 专用配置、请求转换、命令适配或测试场景。

- **AC20（N9、N10）——功能验证边界**
  核心单元测试、功能交互测试、现有完整测试、格式检查、静态检查和编译检查通过；至少
  完成一个简洁的本地终端流程，覆盖大工具结果存盘、自动或手动摘要及后续继续对话。
  测试不连接真实 Anthropic 服务，也不执行压力、长时间、多平台或真实故障注入验证。
