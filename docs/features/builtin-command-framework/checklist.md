# YCode 内置命令框架 Checklist

> 状态：已批准  
> 每一项均通过运行代码、测试或观察真实终端行为验证。

## 注册、解析与分发

- [ ] **AC1——完整命令元数据：** 每条生产命令都具有规范名称、别名集合、描述、用法、
  参数提示、分类、隐藏标记和可调用处理入口。（验证：运行命令契约与内置命令单元测试，
  遍历生产注册表并断言字段完整）

- [ ] **AC1——冲突检测与原子性：** 大小写重复、规范名称重复、别名重复、名称与别名交叉
  占用及同一定义内部重复均在注册时失败并指出冲突项；失败后原注册内容不变。（验证：
  运行注册中心单元测试，分别注入每种冲突并比较失败前后的定义与索引）

- [ ] **AC2——解析和参数保真：** `/PLAN` 大小写无关；`/resume Session-AbC` 保留参数
  大小写；一个或多个空格、Tab 和外层空白产生相同命令语义，参数内部空白保持不变。
  （验证：运行解析器参数化单元测试）

- [ ] **AC3——输入分流：** 普通文本只创建一个 Agent 回合；已注册命令只执行命令处理器；
  未知命令、单独 `/`、`/ help`、`//value` 和命令参数错误均不调用普通 Agent、不写入
  历史并引导使用 `/help`。（验证：运行分发器和终端输入路由测试，检查 Provider 请求与
  会话历史）

- [ ] **AC3、AC15——单活动操作：** Agent 回合或长时间命令运行期间不能启动第二个命令；
  操作结束或取消后可以继续输入。（验证：使用受控异步 Provider 和输入替身运行并发与
  取消测试）

- [ ] **AC15——安全错误：** 用法错误显示对应命令用法，预期业务错误显示可操作摘要，
  未预期异常只显示通用失败信息；任何错误都不包含异常堆栈、秘密或会话正文。（验证：
  注入各类错误并检查终端输出、Provider 请求和历史）

## 帮助与命令目录

- [ ] **AC4——帮助列表：** `/help` 按固定注册顺序列出全部非隐藏生产命令、公开别名和
  简短描述，且没有手工维护的第二份命令清单。（验证：运行内置命令测试并将输出与注册
  表可见定义逐项比较）

- [ ] **AC4——详细帮助：** `/help compact` 显示完整描述、用法和参数提示；使用公开别名
  查询得到所属规范命令的同一份详情；不存在或隐藏目标按未知命令处理。（验证：运行帮助
  参数化单元测试）

- [ ] **AC7——生产命令集合：** 注册表包含 `/help`、`/exit`、`/plan`、`/agent`、
  `/mcp`、`/compact`、`/permission`、`/resume`，且 `/quit` 唯一解析到 `/exit`。
  （验证：遍历 Anthropic 生产注册表并逐项解析名称和别名）

- [ ] **AC7、N6——单一元数据来源：** 新增一个测试定义后，解析、帮助与补全同时可见，
  删除或隐藏后相应入口一致变化，不需要修改其他清单。（验证：使用临时注册中心运行跨
  模块集成测试）

- [ ] **AC14——隐藏命令：** 隐藏测试命令可通过完整名称和别名直接执行，但不出现在
  `/help`、详细帮助查询或 Tab 候选中。（验证：运行注册、帮助、分发和补全联合测试）

## Tab 补全与输入区

- [ ] **AC5——单匹配补全：** 输入唯一命令或别名前缀并按 Tab 后，当前命令词被直接补全，
  不执行处理器、不访问 Provider。（验证：使用 prompt_toolkit 管道输入和控制器计数器
  运行输入框测试）

- [ ] **AC5——多匹配候选：** 输入具有多个公开匹配的前缀并按 Tab 后显示稳定排序的浮动
  候选列表，候选包含规范名称、别名和描述。（验证：运行补全适配测试并在 Windows PTY
  中观察候选菜单）

- [ ] **AC5——补全边界：** 隐藏命令、普通文本、命令参数区、动态会话 ID、权限值和文件
  路径均不产生候选。（验证：运行补全器参数化测试）

- [ ] **AC16——输入提示：** Anthropic 输入区宽屏时左侧显示 `/help for commands`，右侧
  显示当前模式和权限；窄屏优先保留状态并正确缩短或隐藏左侧提示，不破坏四行基础布局。
  （验证：运行多宽度输入框测试并在真实终端观察）

- [ ] **AC16——候选清理：** 补全菜单在提交命令、取消输入和正常退出后不残留在终端滚动
  区。（验证：使用 DummyOutput 和 Windows PTY 分别检查完成后的输出）

## 内置命令行为

- [ ] **AC8——MCP 状态：** `/mcp` 只读取并显示当前 MCP 状态，不调用普通 Agent、不进入
  历史；状态不可用时显示明确错误；额外参数显示命令用法。（验证：运行 MCP 命令单元
  测试，检查状态输出、Provider 请求和历史）

- [ ] **AC9——手动压缩成功：** `/compact` 使用现有隔离摘要流程，成功后保存所需检查点并
  激活新上下文，命令文本不进入普通历史。（验证：使用本地 Fake Provider 运行压缩会话
  测试，检查摘要请求、检查点、历史和报告）

- [ ] **AC9——压缩失败与取消：** 无可压缩历史、摘要无效、检查点存储失败和 `Ctrl+C`
  取消分别显示正确结果，原历史与上下文状态保持安全，取消后可继续对话。（验证：运行
  压缩失败、存储注入和延迟 Provider 取消测试）

- [ ] **AC10——模式切换：** `/plan` 和 `/agent` 按现有规则切换模式，不调用普通 Agent、
  不进入历史，下一次输入提示显示新模式。（验证：运行模式命令与终端下一输入测试）

- [ ] **AC10——权限管理：** `/permission` 查询当前状态；`strict`、`default`、`allow`
  切换模式；`clear` 清除临时授权；非法或多余参数显示用法，所有路径均不调用普通 Agent。
  （验证：运行权限命令参数化测试并检查下一输入提示）

- [ ] **AC11——会话恢复成功：** `/resume <session-id>` 将完整剩余文本作为不透明 ID，
  保留大小写和内部空格；成功切换目标历史、清理临时权限、重置模式与提醒状态并刷新 UI；
  命令不进入历史。（验证：运行多会话恢复单元与集成测试）

- [ ] **AC11——会话恢复失败：** 缺少 ID、目标不存在、恢复压缩失败或存储失败时显示安全
  错误，当前会话、历史、模式和权限保持不变。（验证：注入各失败点并比较操作前后快照）

- [ ] **AC12——退出与别名：** `/exit` 和 `/quit` 走同一正常退出流程；有新增成功回合时
  执行记忆整理，无新增回合时不调用整理模型；EOF 与空闲 `Ctrl+C` 继续复用相同收尾。
  （验证：运行终端退出和记忆整理测试，比较调用次数与输出）

## AI 对话命令与事务

- [ ] **AC13——双文本分流：** 隐藏测试 AI 命令在终端显示原始斜杠输入，普通 Agent 收到
  展开的预设提示词，成功历史和 JSONL 只保存展开提示词且不保存第二份原始命令。（验证：
  使用 Fake Provider、SessionManager 和 UIController 替身检查事件、请求及存档）

- [ ] **AC13、AC15——AI 命令回滚：** AI 命令的 Agent 回合失败、取消或会话写入失败时，
  展开提示词和原始命令都不进入已提交历史；后续普通对话可以正常继续。（验证：分别注入
  Provider、取消和存储失败后重试）

- [ ] **N9——现有事务顺序：** 普通对话和 AI 命令都继续遵循“会话存档成功 → 上下文提交
  → 最终成功事件”的顺序，失败时不提前报告成功。（验证：运行写前提交与事件顺序测试）

## 架构与集成边界

- [ ] **AC6——UI 抽象：** 使用不依赖终端框架的控制器替身可以执行全部处理器并观察用户
  输入、系统消息、AI 提交、模式、权限、状态刷新、恢复和退出请求。（验证：运行内置命令
  处理器单元测试）

- [ ] **N4——依赖方向：** 命令核心不导入 Rich、prompt_toolkit、具体 Console、InputBox
  或 TerminalUI；只有补全适配和 UI 实现依赖终端库。（验证：搜索命令包导入并运行静态
  检查）

- [ ] **N2、N5——确定性启动：** 相同定义顺序产生相同帮助与候选；内置定义冲突或无效时
  Anthropic 启动安全失败，不按注册先后选择命令。（验证：重复构建运行时并注入冲突定义）

- [ ] **N10——显式装配：** 实现中不存在全局注册单例、导入时注册、插件发现、用户命令
  配置或动态命令加载。（验证：检查应用装配和命令包公开入口）

- [ ] **AC18——Provider 隔离：** 只有 Anthropic 会话创建命令运行时；本功能未新增 OpenAI
  配置、Provider 分支或测试场景，OpenAI 当前输入与会话行为未被扩展。（验证：检查 Git
  diff、应用装配并运行现有完整测试）

- [ ] **N3、N8——本地可测性：** 补全、帮助、分发、UI 控制和 AI 测试命令均可使用本地
  替身完成验证，不发起网络请求或调用真实付费 API。（验证：断网环境运行相关单元与 PTY
  测试）

- [ ] **无新增依赖：** 功能只使用项目现有 prompt_toolkit，不新增运行或开发依赖。
  （验证：检查 `pyproject.toml` 依赖 diff）
