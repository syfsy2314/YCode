# YCode 内置命令框架 Spec

> 状态：已批准

## 背景

YCode 当前的内置命令分散在会话层和终端 UI 层：模式、权限、MCP、上下文压缩和
会话恢复由会话层逐项判断，退出命令由终端 UI 单独判断。命令没有统一的元数据、
冲突检测、帮助生成或输入补全入口。

随着会话、记忆、权限和 AI 辅助操作继续增加，继续追加条件分支会使命令发现、参数
处理、测试和 UI 集成逐渐分散。因此需要建立统一的内置命令框架，作为后续命令能力
的稳定扩展点。

## 目标

- 集中定义命令名称、别名、描述、用法、分类、参数提示和处理入口。
- 在用户输入进入普通对话前统一解析和分发斜杠命令。
- 保持命令处理器不依赖具体终端渲染库，通过抽象 UI 控制能力完成交互。
- 为命令名称和别名提供帮助发现与 Tab 补全。
- 将现有 Anthropic 内置命令迁移到统一框架，并保持当前可见行为。
- 支持未来将预设提示词送入普通 Agent 对话的命令类型，第一期不注册此类生产命令。
- 不调整或扩展 OpenAI 路径。

## 功能需求

- F1：系统提供集中式内置命令目录。每条命令包含规范名称、零个或多个别名、简短
  描述、详细用法、参数提示、命令分类、隐藏标记和处理入口。

- F2：注册时对规范名称和别名进行大小写无关的唯一性检查。任意名称与已有规范名称
  或别名冲突时，注册失败并指出冲突项；无效或不完整的命令定义不得进入目录。

- F3：解析器先去除输入两端空白。输入以 `/` 开头时，第一个空白字符前为命令名称，
  后续内容为参数；命令名称转为小写，参数保留原始大小写和内容，仅去除命令与参数
  之间的分隔空白。

- F4：`/` 是保留的命令前缀，第一期不提供 `//` 转义。不存在的命令、单独的 `/`
  以及隐藏命令的帮助查询统一显示未知命令提示，并引导用户使用 `/help`；这些输入
  不得发送给模型或写入历史。

- F5：命令分流发生在 Anthropic 用户输入进入普通 Agent 对话之前。非命令输入继续走
  现有对话流程；已识别命令交给注册中心对应的处理入口。已识别命令携带不支持的
  参数时显示该命令用法，不得退化为普通消息。

- F6：命令处理器只依赖抽象 UI 控制接口，不引用具体终端、Rich 或 prompt_toolkit
  实现。该接口覆盖显示系统消息、提交 AI 用户消息、切换模式、查询状态、刷新状态
  显示以及请求退出等命令所需操作。

- F7：命令保留三类元数据：
  - 纯本地命令：读取和展示本地信息。
  - 状态命令：控制或维护会话、上下文、权限、模式或生命周期；内部可以调用隔离的
    模型服务。
  - AI 对话命令：把预设提示词作为用户消息送入普通 Agent 对话。

  前两类执行各自处理函数，分类不自动施加额外策略；状态刷新由处理函数通过 UI 控制
  接口显式请求。

- F8：AI 对话命令允许根据原始参数生成预设提示词。终端显示用户输入的原始斜杠命令，
  模型收到并写入会话历史的是展开后的提示词，原始命令不另行持久化。第一期只通过
  测试命令验证该分流能力，不注册生产 AI 对话命令。

- F9：新增 `/help`：
  - 无参数时列出所有非隐藏命令的规范名称、公开别名和简短描述。
  - 接收一个规范名称或别名时，显示对应命令的完整描述、用法和参数提示。
  - 内容完全从注册元数据生成，不维护第二份手写命令清单。

- F10：输入框支持命令名称与公开别名的 Tab 补全。单一匹配直接补全，多个匹配显示
  候选列表；隐藏命令不参与补全。第一期不补全命令参数或动态业务数据。

- F11：输入区左侧提示由 `? for help` 改为 `/help for commands`；右侧继续显示当前
  Agent 模式和权限模式。窄终端可以缩短或隐藏左侧提示，不能破坏现有输入布局。

- F12：第一期注册并迁移以下生产命令：
  - `/help`
  - `/exit`，别名 `/quit`
  - `/plan`
  - `/agent`
  - `/mcp`
  - `/compact`
  - `/permission`
  - `/resume`

- F13：迁移后的命令保持现有 Anthropic 行为，包括模式和权限变更、MCP 状态显示、
  可取消的手动压缩、会话恢复失败不切换当前会话、正常退出时整理记忆，以及命令不
  进入普通对话历史。

- F14：隐藏命令可以通过完整名称或别名直接执行，但不会出现在普通帮助列表或 Tab
  候选中；通过 `/help <隐藏命令>` 查询时按未知命令处理。

- F15：命令只在输入空闲状态执行。同一时间不能并行运行命令和 Agent 回合；可取消的
  长时间命令继续支持现有 `Ctrl+C` 取消和状态回滚行为。

- F16：命令参数错误、处理失败或当前能力不可用时，向用户显示安全、可操作的错误
  信息；失败命令不得进入普通历史，也不得意外启动 Agent 回合。

## 非功能需求

- N1：本功能只面向 Anthropic 路径。不得修改或扩展 OpenAI 的配置、Provider、运行
  行为及测试范围。
- N2：命令定义、解析和帮助输出具有确定性；相同注册顺序和输入必须得到相同结果，
  帮助与候选列表保持稳定顺序。
- N3：命令名称补全不得执行命令处理器、访问模型或发起网络请求，输入期间不能因补全
  阻塞终端交互。
- N4：命令核心层不得依赖 Rich、prompt_toolkit 或具体终端对象；具体 UI 框架只能
  出现在 UI 控制接口的实现和补全适配层。
- N5：命令冲突和无效定义必须在应用装配或测试阶段立即暴露，不能等到用户执行时才
  根据注册顺序选择结果。
- N6：新增命令时，命令元数据应自动进入解析、帮助和补全流程，不要求同步修改多个
  手写命令清单或条件分支。
- N7：处理失败时不得输出 API Key、认证头、完整会话正文、记忆正文或内部异常堆栈；
  现有错误脱敏边界继续有效。
- N8：框架、内置命令和 UI 控制接口可使用本地替身独立测试；AI 对话命令的分流测试
  不得调用真实付费 API。
- N9：现有流式对话、工具审批、取消、上下文事务、会话写前提交和退出记忆整理的顺序
  保证不得因命令迁移而削弱。
- N10：实现保持当前项目规模所需的最小复杂度，不引入全局注册单例、导入时自动注册、
  第三方命令插件加载或动态配置命令。

## 不做的事

- 不修改、适配或补充测试 OpenAI 路径；OpenAI 命令框架适配留到项目整体功能完成后
  的独立 Spec。
- 不实现 `/clear`、`/sessions`、`/memory`、`/status`、`/review` 等新增业务命令。
- 不注册生产环境的 AI 对话型命令，只验证框架具备该分流能力。
- 不把 CLI 参数（包括 `--continue`）纳入斜杠命令注册中心。
- 不支持用户自定义命令、项目级命令配置、第三方插件命令或运行时动态加载。
- 不支持动态参数补全，例如会话 ID、权限模式、文件路径或 MCP Server 名称。
- 不设计命令管道、命令串联、重定向、引号语法、多行命令或嵌套命令。
- 不提供 `//` 转义；所有以 `/` 开头的输入均进入命令解析。
- 不重做现有模式、权限、MCP、上下文、会话和记忆业务逻辑，只将已有入口迁移到命令
  框架。
- 不重新设计输入框或状态栏视觉样式，只替换帮助提示并接入命令补全。
- 不增加 YAML 配置项控制命令显示、别名、排序或快捷键。
- 不进行压力测试、性能基准、多终端框架矩阵或真实付费 API 验证。

## 验收标准

- AC1（F1、F2）：注册包含完整元数据的命令后，可以按规范名称和别名查询；名称大小写
  冲突、别名冲突、名称与别名交叉冲突及无效定义均在注册时失败，并明确指出冲突项。

- AC2（F3）：输入 `/PLAN`、`/resume Session-AbC` 和带外层空白的命令时，命令名称
  大小写无关，参数 `Session-AbC` 保持原始大小写；名称与参数可由一个或多个空白字符
  分隔。`/resume` 将命令词后的完整剩余文本视为不透明会话 ID，允许其中包含空格。

- AC3（F4、F5）：普通文本只进入一次 Agent 对话；已注册命令只进入命令分发；未知
  命令、单独 `/` 和参数错误均显示帮助引导，不调用普通 Agent，也不写入历史。

- AC4（F9、F14）：`/help` 按稳定顺序列出全部非隐藏生产命令、公开别名和描述；
  `/help compact` 与通过公开别名查询显示同一份详细用法和参数提示；隐藏命令不被
  列出或查询。

- AC5（F10）：在真实输入框中输入命令前缀并按 Tab，单一匹配直接补全，多匹配显示
  稳定候选列表；规范名称和公开别名可补全，隐藏命令和参数候选不会出现。

- AC6（F6）：使用不依赖终端框架的 UI 控制替身，可以独立执行命令处理器并观察系统
  消息、AI 消息提交、模式变化、状态刷新和退出请求；命令核心模块不导入具体终端
  渲染库。

- AC7（F7、F12）：注册中心包含 `/help`、`/exit`、`/plan`、`/agent`、`/mcp`、
  `/compact`、`/permission`、`/resume`，其中 `/quit` 解析到 `/exit`；帮助、补全和
  实际分发使用同一组注册定义。

- AC8（F12、F13）：执行 `/mcp` 只读取并显示当前 MCP 状态，不调用普通 Agent；MCP
  状态不可用时显示明确错误，命令不进入历史。

- AC9（F12、F13、F15）：执行 `/compact` 继续使用现有隔离摘要流程并更新上下文检查点，
  不进入普通对话历史；无可压缩内容、摘要失败、存储失败和 `Ctrl+C` 取消时保持现有
  安全回滚行为。

- AC10（F12、F13）：执行 `/plan`、`/agent` 和 `/permission` 后，模式或权限状态按
  现有规则变化并刷新输入区状态；查询、非法参数和清除临时授权保持现有行为，均不
  调用普通 Agent。

- AC11（F12、F13）：执行 `/resume <session-id>` 成功时切换目标历史并刷新相关状态；
  完整剩余文本按原样作为会话 ID，参数缺失、目标不存在或恢复失败时当前会话保持不变，
  命令不进入历史。

- AC12（F12、F13）：执行 `/exit` 或别名 `/quit` 时走同一正常退出流程；存在新成功
  回合时继续执行退出记忆整理，没有新回合时直接退出。

- AC13（F8）：注册一个仅用于测试的 AI 对话命令后，终端侧观察到原始斜杠输入，普通
  Agent 收到并持久化展开后的预设提示词；原始命令不作为第二条历史消息保存。

- AC14（F14）：隐藏测试命令可通过完整名称或别名执行，但不会出现在 `/help`、详细
  帮助查询或 Tab 候选中。

- AC15（F15、F16）：Agent 回合或长时间命令运行期间不能启动第二个命令；取消或处理
  异常后可以继续输入，错误不会触发普通 Agent、污染历史或泄露敏感内容。

- AC16（F11）：真实终端等待输入时，左侧显示 `/help for commands`，右侧继续显示当前
  模式和权限；窄终端布局不溢出、不破坏输入区域，提交或退出后不残留动态候选区域。

- AC17（N8、N9）：Anthropic 的流式对话、Thinking、工具循环、审批、plan-only、MCP、
  上下文压缩、会话恢复和退出记忆流程测试通过，并在真实 PTY 中完成帮助、补全、模式
  切换、压缩和安全退出流程。

- AC18（N1、N10）：本功能不新增 OpenAI 配置、Provider 行为或测试场景，也不引入
  全局注册、自动发现、插件加载或命令配置机制。
