# 子 Agent Worktree 隔离 Spec

> 状态：已批准

## 背景

YCode 已支持同步和异步子 Agent，但父子 Agent 当前共享同一个项目文件系统和工具执行根目录。多个具备写权限的 Agent 并行修改代码时，可能覆盖彼此的文件、观察到中间状态，或在同一 Git 工作区中产生难以归属的变更。

Git Worktree 可以让同一仓库的不同分支拥有独立工作目录，适合作为写入型子 Agent 的本地隔离基础。YCode 需要在现有子 Agent 系统上增加可选的 Worktree 隔离模式，同时统一管理安全命名、环境初始化、任务归属、变更保留、删除保护和异常退出后的状态识别。

该能力只服务于子 Agent 协作。主 Agent 始终在启动时的主仓库工作，不进入或切换 Worktree。YCode 也不修改进程级工作目录；每个 Agent 通过独立的工作区路径执行文件、命令、Git 和 Hook 操作。

## 目标

- 允许项目角色声明是否需要独立 Git Worktree。
- 为每个隔离子 Agent 自动创建唯一的本地 Worktree 和临时分支。
- 让隔离子 Agent 的全部工作区相关操作显式绑定到其 Worktree，避免并发串目录。
- 复用主仓库的配置、会话和共享 Memory，同时从 Worktree 加载对应版本的项目指令。
- 初始化 Worktree 所需的本地配置、Git Hooks、依赖链接和被忽略运行文件。
- 在子 Agent 结束时根据实际变更决定自动清理或保留，并向主 Agent 返回可整合的 Git 摘要。
- 由主 Agent 在用户明确授权后检查和整合多个子 Agent 的成果，不自动提交或合并。
- 持久化 Worktree 管理状态，使异常退出后的目录能够被识别、保护和清理，但不恢复子 Agent 执行。
- 提供查看状态、安全删除和启动时过期清理能力。
- 保持普通主 Agent、未声明隔离的子 Agent 及现有 OpenAI 路径行为不变。

## 功能需求

### 隔离声明与适用范围

- **F1：角色隔离声明。** 项目子 Agent 角色支持 `isolation: none | worktree`，默认值为 `none`。未知值或格式错误使该角色不可用。
- **F2：创建模式。** `worktree` 隔离同时适用于定义式同步和异步子 Agent。无角色 Fork 和未声明隔离的角色继续共享主仓库。
- **F3：禁止嵌套。** 继续沿用现有规则：任何子 Agent 都不能创建其他子 Agent。
- **F4：隔离失败确认。** 当 Git 不可用、仓库无初始 commit 或 Worktree 创建失败时，不得静默退化。任务不启动并向主 Agent 返回明确原因；只有用户为本次任务显式允许后，才能重新以共享主仓库方式运行。

### Worktree 创建与身份

- **F5：自动创建。** 一个隔离子 Agent 对应一个由 YCode 自动创建的 Worktree 和临时分支。不提供手动创建入口。
- **F6：创建基准。** Worktree 从主 Agent 当前 HEAD 创建，不包含主仓库中的 staged、modified 或 untracked 内容。
- **F7：受管目录。** 所有额外 Worktree 存放在主仓库 `.ycode/worktrees/` 下，该目录不被 Git 跟踪。YCode 从受管 Worktree 内启动时拒绝运行并提示返回主仓库。
- **F8：安全名称。** 逻辑名称由 YCode 根据角色和任务 ID 生成，不使用任务正文或模型输出。名称只允许 ASCII 小写字母、数字、点、下划线和连字符，以 `/` 分段；拒绝空段、`.`、`..`、反斜杠、Windows 保留名称、段尾点和连续 `--`。最多 4 段、每段最多 32 个字符、完整名称最多 96 个字符。
- **F9：分支映射。** 临时分支统一位于 `ycode/` 命名空间，逻辑名称中的 `/` 转换为 `--`，映射必须无碰撞且可逆。
- **F10：名称冲突。** 自动名称对应的目录或来源不明分支发生冲突时，YCode 自动生成新的任务后缀并有限次重试，不接管、覆盖或删除已有内容。
- **F11：快速恢复。** 创建时发现目标目录已存在，只有有效的 YCode 管理记录和可验证的 `.git` 指向同时存在时，才通过纯文件系统读取当前 HEAD 并恢复登记，不调用 Git 子进程。元数据缺失、损坏或不匹配时保留现场并报错。

### 环境初始化

- **F12：初始化配置。** Worktree 初始化规则由主仓库 `.ycode/config.yaml` 的 Worktree 配置段统一提供，子 Worktree 不复制该配置。
- **F13：本地文件复制。** 配置可以显式列出需要复制的仓库相对本地文件。YCode 不内置特定框架文件名；源文件缺失、复制失败或目标已存在时不覆盖，并记录初始化警告。
- **F14：忽略文件规则。** 配置可以使用安全的仓库相对 Glob 复制 Git 忽略但运行需要的普通文件。绝对路径、`..`、越界匹配、非忽略文件、目录链接和目录外目标不得复制；单项失败只记录警告。
- **F15：依赖目录链接。** 配置可以显式列出大型依赖目录。Linux 和 macOS 使用目录符号链接，Windows 允许使用 Junction；源不存在、目标已存在或链接失败时记录警告并继续。
- **F16：Git Hooks。** Worktree 必须与主仓库使用同一个有效 Git Hooks 目录。主仓库未配置自定义 `core.hooksPath` 时沿用 Git 默认 Hooks；不能确认两者一致时初始化失败。
- **F17：失败分级。** Worktree 创建、管理记录写入和 Git Hooks 配置属于关键步骤，失败时回滚本次创建；本地文件复制、忽略文件复制和依赖链接属于 best-effort，失败不阻止子 Agent 启动，但必须汇总告警。

### Agent 工作区运行

- **F18：路径驱动。** YCode 不修改进程级工作目录。每个 Agent 持有独立且不可由模型覆盖的绝对工作区路径；文件、搜索、命令、Git、环境采集和 Hooks 都从当前 Agent 运行上下文取得该路径。
- **F19：工具隔离。** Worktree 隔离子 Agent 使用独立的工作区工具实例、路径解析、权限执行上下文和临时资源；Provider、已建立的外部连接及与路径无关的基础设施按现有规则共享。
- **F20：工具参数。** 模型继续使用工作区相对路径。命令工具可以指定当前 Agent 工作区内的相对子目录，但不能修改工作区根或访问其他 Worktree。
- **F21：项目上下文。** 隔离子 Agent 使用任务派发时已验证的角色快照，从自己的 Worktree 重新加载 `YCODE.md` 及引用文件，并从主仓库重新读取共享项目 Memory。项目 Memory 对子 Agent 只读，子 Agent 完成时不更新 Memory。
- **F22：路径说明。** 隔离任务保留原始任务正文，并在其前面注入可信的父工作区与子 Worktree 路径映射说明。相对路径在子 Worktree 内解析；父工作区绝对路径按映射转换，不直接重写原始任务文本。
- **F23：YCode Hooks。** 隔离子 Agent 执行现有回合、消息、工具、上下文压缩和 Agent 错误 Hooks，不重复会话开始与结束事件。它复用主进程已验证的规则，但独立维护 `once`、Reminder 和运行状态；Shell Hook 以子 Worktree 为执行路径。普通子 Agent 继续共享现有 Hook 状态。
- **F24：独占访问。** Worktree 在任务运行期间由创建它的“会话 ID + 任务 ID”独占。其他 Agent 和会话不能通过 YCode 的文件/搜索工具访问，也不能把它作为命令工具的 `cwd`，不能删除或接管；主 Agent 的提示词同时明确禁止在命令正文中显式访问活动 Worktree。现有 PowerShell 命令安全机制不提供操作系统级文件系统沙箱，因此不承诺拦截命令正文中构造出的所有路径访问。任务结束并进入保留状态后，主 Agent 才能显式检查和整合。

### 完成、结果与整合

- **F25：完成检查。** 子 Agent 进入任一终态时，YCode 检查相对创建基准的新 commit，以及 staged、modified 和 untracked 内容。
- **F26：自动清理。** 相对创建基准没有任何 commit 或工作区变更时，自动删除 Worktree 和对应临时分支。
- **F27：变更保留。** 存在新 commit 或工作区修改时保留 Worktree 和分支。任务失败、取消或达到轮次上限但留下变更时同样保留。
- **F28：结果摘要。** 子 Agent 结果包含 Worktree 逻辑名称、绝对路径、分支、创建基准、当前 HEAD、工作区状态、commit 列表、diff stat 和初始化警告。完整 diff 由主 Agent 按需检查。
- **F29：提交边界。** YCode 不自动提交，也不强制子 Agent 提交。未提交成果继续保留在其 Worktree 中。
- **F30：合并边界。** Worktree 管理器和子 Agent 不自动 merge、rebase 或 cherry-pick。主 Agent 在用户明确授权后检查各分支并依次整合；无法判断的冲突交由用户决定。

### 状态持久化与并发归属

- **F31：管理记录。** 主仓库持久化每个 Worktree 的名称、路径、分支、基准、当前状态、创建时间、最后活动时间、初始化告警、所属会话、任务和进程信息。
- **F32：生命周期状态。** 管理记录至少区分 `creating`、`active`、`retained` 和 `interrupted`。
- **F33：多会话归属。** 多个会话可以同时使用不同 Worktree。同一个 Worktree 同时只能由一个会话和任务持有；进程 ID 只用于辅助存活判断，不作为唯一身份。
- **F34：异常退出。** YCode 重新启动时，失去有效占用者的 `active` Worktree 标记为 `interrupted` 并保留。原任务和结果不恢复，`/tasks` 继续只展示当前进程任务。
- **F35：会话恢复。** `--continue` 继续恢复最近会话，`/resume <session-id>` 继续恢复指定会话。恢复时可以通过持久化记录识别该会话遗留的 Worktree，但不自动重启子 Agent。`/resume` 空参数行为不变，仍显示用法错误。

### 状态、删除与清理

- **F36：状态查询。** `/worktree list` 展示受管 Worktree 摘要；`/worktree status <name>` 展示路径、分支、基准、HEAD、归属、生命周期、工作区状态、upstream、未推送 commit、时间、告警和删除阻止原因。
- **F37：安全删除。** `/worktree delete <name>` 同时删除 Worktree 和对应 YCode 临时分支。运行中、存在未提交修改或存在无法确认已安全推送的新 commit 时默认拒绝。
- **F38：推送判断。** 没有新增 commit 且工作区干净时，即使没有 upstream 也可以删除；存在新增 commit 但没有 upstream 时视为无法确认已推送。检查只使用本地 Git 和远端跟踪状态，不自动 fetch 或访问网络。
- **F39：强制丢弃。** `/worktree delete <name> --force` 先显示未提交和未推送摘要，再要求用户进行一次交互确认。子 Agent 和自动清理不能执行强制删除。
- **F40：失败关闭。** Git 状态、upstream、管理记录或占用状态无法可靠确认时，不执行普通删除或自动清理，并保留目录。
- **F41：过期规则。** 只有 YCode 自动创建的 `agents/...` Worktree 参与过期清理。过期时间从最后活动时间计算，默认 24 小时，并允许通过主仓库配置修改。用户不拥有手动创建入口。
- **F42：启动清理。** YCode 每次启动时执行一次清理扫描，不运行周期后台任务。扫描依次验证受管命名和元数据、无人占用与已经过期、无未提交和未推送变更，全部通过才删除。
- **F43：手动清理。** `/worktree cleanup` 立即执行与启动清理相同的安全流程。单个候选检查或删除失败时保留该候选、汇总警告并继续，不阻止应用运行。
- **F44：命令范围。** 本期只提供 `/worktree list`、`/worktree status <name>`、`/worktree delete <name> [--force]` 和 `/worktree cleanup`；不提供手动创建、进入或退出。

## 非功能需求

- **N1：Provider 范围。** 本期只开发和验收 Anthropic 路径；核心 Worktree 管理与 Agent 工作区上下文保持 Provider 无关。OpenAI 不接入本功能。
- **N2：路径安全。** 角色配置、模型文本、任务内容、配置路径和磁盘元数据均不能绕过主仓库与受管 Worktree 边界。所有实际目标必须经过规范化和越界校验。
- **N3：并发隔离。** 在现有可配置子 Agent 并发上限内，不同 Agent 的工作区路径、工具状态、权限、Hooks、临时资源和文件操作不得串用。同一 Worktree 的独占规则必须在 YCode 的工作区感知工具解析路径或命令 `cwd` 前生效；不把任意 PowerShell 命令正文纳入操作系统级文件系统隔离保证。
- **N4：默认安全失败。** 无法确认目录身份、占用者、Git 状态、upstream、Hooks 路径或删除安全性时，必须保留现场并拒绝危险操作。
- **N5：确定性。** 相同的合法逻辑名称必须得到相同分支映射；相同 Worktree 状态和本地 Git 信息必须产生相同的保留、删除及清理判断。
- **N6：本地数据保护。** 初始化过程不得在日志、结果或错误中输出被复制本地文件的正文、密钥或环境变量。目标已存在时不得覆盖。
- **N7：无隐式网络操作。** 创建、状态检查、变更保护和清理不得自动执行 fetch、push 或其他远端操作；“已推送”只依据本地 upstream 与远端跟踪信息判断。
- **N8：现有功能兼容。** 未使用 `isolation: worktree` 时，主 Agent、普通子 Agent、Fork、任务命令、权限、Hooks、Memory、Session、Skill、MCP 和工具行为保持不变。现有 `/resume <session-id>` 和 `--continue` 契约保持不变。
- **N9：受控规格例外。** 只有 Worktree 隔离子 Agent 改用独立工作区工具和独立 Hook 运行状态；普通子 Agent 继续共享现有工具基础设施及会话级 Hook `once` 状态。
- **N10：基本故障恢复。** Worktree 管理记录必须足以在正常退出或意外退出后识别、保护和清理目录；不要求恢复模型请求、工具调用现场或子 Agent 执行。
- **N11：功能性验证。** 使用本地临时 Git 仓库、Provider 替身和文件系统夹具验证核心创建、隔离、初始化、保护、恢复及清理行为；CLI、子 Agent 和对话流程使用真实终端端到端场景验证。
- **N12：非生产级验证。** 不进行压力测试、性能基准、长时间稳定性运行、大规模并发、复杂竞态或故障注入、多平台矩阵、真实付费 API、真实远端推送及网络可靠性测试。
- **N13：不过度建设。** 不增加分布式锁、持久化任务队列、自动重试系统、监控指标、审计平台或为理论边界设计的额外抽象；只实现已确认的功能性占用保护和磁盘状态恢复。
- **N14：启动负载。** 不运行周期后台扫描。启动清理只检查 YCode 管理记录和受管命名空间，不遍历主仓库的无关目录。
- **N15：实现一致性。** 遵循现有项目结构和安全边界；新增代码保持简洁，不为未来 Provider 或未批准的工作区模式提前扩展。

## 不做的事

- 不接入、修改或补充 OpenAI 的 Worktree、子 Agent、Session、命令或验收行为。
- 不让主 Agent 进入、退出或切换 Worktree；主 Agent 始终以启动时的主仓库为工作区。
- 不修改进程级 `cwd`，也不依赖全局工作目录实现 Agent 隔离。
- 不提供手动创建、命名、认领或导入外部 Worktree 的能力。
- 不为无角色 Fork 自动创建 Worktree。
- 不允许子 Agent 创建其他子 Agent。
- 不把主仓库中的 staged、modified、untracked 或 stash 内容同步到新 Worktree。
- 不自动 commit、merge、rebase、cherry-pick、解决冲突、生成集成分支或建立合并队列。
- 不自动 fetch、pull、push、创建远端分支或调用托管平台 API。
- 不恢复异常退出前的模型请求、工具调用、子 Agent 任务执行现场或 `/tasks` 历史记录。
- 不为每个 Worktree 创建独立 Session、Memory、Skill、Provider 配置或外部连接。
- 不允许隔离子 Agent 更新共享项目 Memory。
- 不改变普通子 Agent 现有的共享文件系统、工具基础设施和会话级 Hook `once` 语义。
- 不改变 `/resume <session-id>` 的必填参数行为，也不新增 CLI `--resume`。
- 不运行周期性后台清理、文件监听或常驻维护服务。
- 不覆盖 Worktree 中已存在的初始化目标，不自动修复损坏或来源不明的目录、分支和元数据。
- 不建设容器、虚拟机、文件系统快照或操作系统账户级沙箱；隔离边界仅基于 Git Worktree、工作区感知工具的路径限制、命令 `cwd` 限制和提示词规则。
- 不实现分布式锁、远程协调、组织级 Worktree 服务、持久化任务队列或跨机器恢复。
- 不执行压力测试、性能基准、长期稳定性、大规模并发、复杂竞态或故障注入、多平台矩阵、真实远端仓库或真实付费 API 验证。
- 不为尚未确认的未来隔离方式、远端 Agent 或复杂编排提前设计扩展。

## 验收标准

- **AC1（F1–F4）隔离声明。** 合法角色可以使用 `none` 或 `worktree`，省略时保持现有共享行为；非法值只使该角色不可用。同步和异步定义式角色均能触发隔离，无角色 Fork 不触发。隔离环境不可用时任务不会启动或静默降级，主 Agent 能向用户请求一次性共享执行授权。
- **AC2（F5–F11）安全创建。** 隔离子 Agent 从主 Agent 当前 HEAD 获得唯一 Worktree 和临时分支，主仓库未提交内容不出现在其中。目录和分支符合已约定的命名、长度、位置及平铺映射规则；自动冲突会换名重试，不接管已有内容。从受管 Worktree 启动 YCode 会被拒绝。有效残留目录可以不调用 Git 子进程完成快速恢复，损坏或不匹配现场保持不变。
- **AC3（F12–F17）环境初始化。** 主仓库配置能够控制显式本地文件复制、Git 忽略文件 Glob 复制和大型依赖目录链接；非法路径、越界结果、非忽略文件、目录链接和已有目标不会被覆盖。Windows 可观察到 Junction 行为。子 Worktree 与主仓库使用同一有效 Git Hooks 目录；关键步骤失败会回滚创建，best-effort 项目失败只产生不含文件正文或密钥的告警。
- **AC4（F18–F20）路径驱动工具。** 进程级工作目录在主 Agent 和多个隔离子 Agent 运行前后保持不变。每个 Agent 的文件、搜索、命令、Git 和环境信息都作用于各自工作区；相对路径正确解析，模型不能覆盖工作区根，也不能通过绝对路径、`..`、符号链接或 Junction 越界到其他工作区。
- **AC5（F21–F24）上下文、Hooks 与占用。** 隔离子 Agent 使用任务派发时的角色快照、Worktree 内的 `YCODE.md` 和重新读取的共享只读 Memory；任务中的父目录绝对路径能够依据可信映射转换。隔离子 Agent 触发非会话级 Hooks，Shell Hook 在其 Worktree 执行，`once`、Reminder 和运行状态不与父 Agent 混用。任务运行期间，其他 Agent 和会话通过文件/搜索工具访问、把该目录作为命令 `cwd` 或删除该 Worktree 会被拒绝，主 Agent 同时收到不得在命令正文中访问活动 Worktree 的规则；进入保留状态后主 Agent 可以显式检查。
- **AC6（F25–F28）完成判定。** 子 Agent 正常完成、失败、取消或达到轮次上限时，系统都检查基准差异。没有新 commit、staged、modified 或 untracked 内容时自动删除目录和分支；存在任一变更时保留。结果能够观察到名称、路径、分支、基准、HEAD、工作区状态、commit 列表、diff stat 和初始化警告。
- **AC7（F29–F30）提交与整合边界。** 隔离子 Agent 产生未提交修改时不会被 YCode 自动提交；多个子 Agent 完成后不会发生自动 merge、rebase 或 cherry-pick。主 Agent 只有在用户明确授权后才执行检查和逐个整合，无法判断的冲突不会被自动解决。
- **AC8（F31–F35）持久化与会话归属。** 管理记录能够跨进程保存完整 Worktree 身份、生命周期、时间、警告和所有者。两个会话可以同时占用不同 Worktree，但不能占用同一个。模拟异常退出后，遗留的活动 Worktree 在下次启动时标记为 `interrupted` 并保留，原子 Agent 任务和 `/tasks` 历史不恢复。`--continue`、`/resume <session-id>` 及 `/resume` 缺参行为保持现有契约。
- **AC9（F36–F40）状态与安全删除。** `/worktree list` 和 `/worktree status <name>` 能显示规定的摘要和详情。普通删除会同时移除 Worktree 与临时分支；运行中、存在未提交内容、新 commit 无 upstream、存在未推送 commit 或任一检查失败时拒绝删除。无新增 commit 且目录干净时不因缺少 upstream 被误阻止。`--force` 会显示风险摘要并要求二次确认，取消确认后现场不变。
- **AC10（F41–F44）过期清理。** 启动和 `/worktree cleanup` 只扫描 YCode 自动创建的受管临时 Worktree，按最后活动时间和配置 TTL 判断过期，并依次应用命名、占用、过期、变更和推送检查。只有全部通过的候选被删除；单项失败会保留候选、汇总告警并继续。等待超过一个清理周期不会出现后台扫描。命令帮助中只出现 list、status、delete 和 cleanup，不出现 create、enter 或 exit。
- **AC11（N1–N10）安全与兼容。** 无法确认路径、身份、Git、Hooks、占用或删除安全性时均保持 fail-closed；初始化和错误输出不泄露本地配置内容及密钥，不产生隐式网络访问。未使用 Worktree 隔离时，普通子 Agent、Fork、父 Agent、Hooks、权限、Memory、Session、Skill、MCP、命令及 OpenAI 现有路径的回归测试保持通过。
- **AC12（核心端到端）真实协作流程。** 在真实终端中，由主 Agent 创建两个使用 Worktree 隔离的子 Agent；观察到两个不同目录和分支、独立文件修改、正确完成通知和变更保留。主 Agent 不能在任务运行期间写入其目录；用户授权整合后可以检查成果。安全删除完成后目录和临时分支消失，主仓库未授权内容不被修改。
- **AC13（N11–N15）验证边界。** 使用本地临时 Git 仓库、模拟 Provider 和代表性文件系统场景完成单元、集成、编译、格式、静态检查及真实终端端到端验证；不调用真实付费 API 或真实远端服务，也不执行压力、性能、长期稳定性、大规模并发、复杂竞态、故障注入或多平台矩阵验证。
