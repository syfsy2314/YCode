# YCode 记忆系统 Spec

> 状态：已批准

## 背景

YCode 当前只在进程内维护会话历史，并在上下文过长时生成临时滚动摘要；退出后不会
保存会话，也不会读取项目指令或维护跨会话项目记忆。本功能将替代已有功能文档中
“会话历史不持久化”“不发现项目指令文件”以及“不管理跨会话记忆”的旧边界，建立
统一的项目上下文、会话存档与项目记忆系统。

## 目标

- 启动时安全读取项目根目录的 `YCODE.md`，支持受限的模块化引用。
- 由统一的会话存储管理入口负责会话创建、恢复、列表和删除。
- 使用 JSONL 保存结构化消息，并保证落盘成功后才提交内存历史。
- 通过 `.ycode/memory/MEMORY.md` 向模型提供记忆索引，详细内容由模型按需读取。
- 正常退出时由隔离的 LLM 请求分析本次运行新增对话，自动创建、更新、合并或删除
  四类项目记忆。
- 项目指令、会话恢复和记忆注入在上下文压缩后仍然保持正确语义。
- 核心设计保持 Provider 无关，当前只对 Anthropic 路径进行实际接入和验收。

## 功能需求

### 项目指令

- **F1：项目根目录**  
  项目根目录由活动配置文件的位置确定：自动发现配置时使用最近的
  `.ycode/config.yaml` 所在目录；显式配置时使用指定配置文件所在目录。

- **F2：指令发现与快照**  
  启动时读取项目根目录的 `YCODE.md`。文件不存在时正常启动；存在时读取一次并作为
  本次运行的只读快照，运行期间的文件修改需重启后生效。

- **F3：模块化引用**  
  `YCODE.md` 支持独占一行的 `@include <relative-path>`。路径相对于当前包含文件解析，
  `YCODE.md` 为第 0 层，最多引用到第 5 层，并检测循环引用。绝对路径、目录逃逸、
  符号链接逃逸、文件缺失、循环或超深均导致启动失败，并指出来源文件和引用位置。

- **F4：指令注入**  
  展开后的项目指令作为独立系统级上下文参与每次模型请求，不伪装成用户消息、不写入
  会话存档，也不会因上下文压缩而消失。

### 会话存档与恢复

- **F5：统一会话存储管理**  
  一个统一的会话存储管理入口独占维护 `.ycode/sessions/`，提供创建、恢复、列出和删除
  会话的能力。删除只接受精确会话 ID，且不得删除当前活动会话。活动对话、模式、权限
  和事件流仍由对话会话层负责，不合并进会话存储管理职责。

- **F6：会话标识与文件**  
  每个会话保存为 `.ycode/sessions/<session-id>.jsonl`，不创建额外 meta 文件。会话 ID
  使用本地时间 `YYYYMMDD-HHmmss` 加第一条用户消息生成的小标题；标题保留中文、合并
  空白、删除 Windows 非法字符并限制为 32 个字符，重名时追加数字后缀。

- **F7：JSONL 记录**  
  每行保存一条完整、版本化的结构化记录，包括 UTC 时间。消息记录覆盖用户消息、
  Assistant 文本、Thinking、工具调用和工具结果；不保存流式增量或 TUI 展示事件。
  完整回合使用提交边界记录标识。

- **F8：写前提交**  
  正常完成的回合先完整追加到 JSONL 并刷新写入，再提交到内存历史并向界面报告最终
  完成。写入失败时不得提交内存历史。取消、模型错误和轮数超限的回合不提交。

- **F9：启动、恢复与切换入口**  
  默认启动创建新会话；`--continue` 恢复时间戳最新的会话；`/resume <session-id>` 在
  空闲状态恢复指定会话。斜杠命令不进入历史。恢复失败时当前会话保持不变；当前已有
  对话时也允许切换，原会话保留在存档中。列出和删除暂时只提供程序接口，留给后续
  斜杠指令使用。

- **F10：解析容错**  
  恢复时逐行读取 JSONL。无法解析的行跳过并产生简洁警告，其余记录继续参与校验。

- **F11：结构修复**  
  恢复时校验回合边界、消息顺序以及 `tool_use`/`tool_result` 配对。发现不完整结构时
  只保留最后一个完整提交边界之前的历史，实际截断原 JSONL，并提示发生了修复。

- **F12：恢复压缩**  
  恢复后的上下文超过自动压缩阈值时，在进入交互状态前只尝试一次压缩。成功后追加
  包含摘要、覆盖边界和 UTC 时间的上下文检查点，原始消息不删除；后续恢复使用最新
  有效检查点及其后的消息。压缩失败时保留原文件、终止本次恢复，不静默创建新会话
  或继续发送超限请求。

- **F13：时间跨度提醒**  
  恢复会话距最后活跃时间至少 24 小时时，在恢复后的第一次模型请求中注入一次系统级
  提醒，包含本地展示的上次活跃时间、当前时间和间隔；提醒不进入历史且不重复注入。

- **F14：会话切换状态隔离**  
  `/resume` 只恢复对话历史和最新上下文检查点。任务模式重置为 `agent`，会话级临时
  权限被清除，上下文压缩失败计数和熔断状态重置，下一请求重新注入完整模式提醒。
  项目指令和记忆索引继续使用本次启动时的快照；MCP 连接和工具注册继续复用当前
  应用实例。

### 项目记忆

- **F15：记忆目录与分类**  
  项目记忆位于 `.ycode/memory/`。`MEMORY.md` 是单层索引，每条主题记忆对应一个
  Markdown 文件。四类文件使用固定前缀：`user-*`、`feedback-*`、`project-*` 和
  `reference-*`。

- **F16：主题文件格式**  
  每个主题文件使用 YAML front matter，包含 `name`、`description` 和 `type`。
  `type` 只能是 `user_preference`、`correction_feedback`、`project_knowledge` 或
  `reference`，并须与文件名前缀一致。

- **F17：记忆索引**  
  索引项使用固定格式：

  ```markdown
  - [名称](relative-file.md) — 简短说明
  ```

  名称与说明分别对应主题文件中的 `name` 和 `description`。索引只允许直接指向同一
  记忆目录内的主题文件，不允许嵌套索引。

- **F18：记忆加载与注入**  
  普通模型请求只注入有效的 `MEMORY.md` 索引，不注入主题正文。模型需要细节时使用
  现有 `read_file` 工具读取。索引或主题文件缺失、格式错误时跳过对应内容并警告；
  绝对路径和目录逃逸始终拒绝，但记忆错误不阻止 YCode 启动。记忆文件不解析
  `@include`。

- **F19：退出时记忆分析**  
  取消按固定回合数更新记忆。只有正常退出且本次运行产生了新的成功回合时，才执行
  一次隔离、无工具的 LLM 请求。输入包括本次运行期间所有访问过的会话中新产生的
  已提交对话、各回合所属的会话 ID 和时间边界、当前有效索引及其引用的全部记忆正文。

- **F20：记忆决策**  
  模型按四类记忆判断是否需要变更，可以返回无需更新、新建、更新、合并或删除。
  重复和语义相似性完全由模型判断，程序不实现相似度算法。

- **F21：安全应用**  
  YCode 校验模型返回的类别、路径、front matter 和索引一致性后自动应用，不逐项请求
  确认。变更范围只能位于 `.ycode/memory/`，删除仅限当前索引引用的主题文件；校验
  或写入失败时保留原有效记忆并显示非致命提示。

- **F22：退出触发与等待**  
  `/exit`、`/quit` 和空闲状态的 `Ctrl+C` 均触发记忆分析。退出最多等待 30 秒；超时
  或调用失败时保留原记忆后退出。没有新增成功回合时不调用模型。强制终止、进程崩溃
  和断电不保证执行记忆整理。

## 非功能需求

- **N1：路径安全**  
  所有项目指令引用、记忆索引和主题文件路径都必须经过真实路径解析与项目边界校验，
  不能通过绝对路径、`..` 或符号链接读取项目外文件。

- **N2：会话一致性**  
  JSONL 是持久化会话的事实来源。只有完整记录成功刷新后才能更新内存历史；恢复和
  切换不得让磁盘历史与活动历史处于不同提交状态。

- **N3：崩溃恢复边界**  
  每次追加后刷新进程缓冲，普通进程异常退出时只允许尾部回合受损，并能在恢复时修复。
  不承诺断电、操作系统崩溃或磁盘故障下的同等级持久性。

- **N4：原子记忆更新**  
  自动记忆变更必须先完整校验并准备目标文件，再原子替换索引，最后清理不再引用的
  文件。更新中断时，已有索引仍应只指向完整可读的记忆；遗留但未被索引引用的文件
  不进入模型上下文。

- **N5：失败隔离**  
  项目指令无效时明确阻止启动；可选记忆损坏只产生警告；记忆整理失败不影响会话存档；
  恢复目标失败时不破坏当前活动会话。

- **N6：上下文控制**  
  普通请求只注入记忆索引，主题正文由模型按需读取。项目指令、项目记忆和会话压缩摘要
  必须保持不同来源与语义边界，不把自动记忆当作代码事实。

- **N7：性能边界**  
  会话消息采用追加写入，不因历史增长而重写整个 JSONL。列出会话时只根据文件名取得
  ID 和创建时间，不扫描全部消息；恢复时只读取被选中的会话文件。

- **N8：隐私与本地存储**  
  会话与项目记忆只保存在当前项目的 `.ycode/` 下并默认被 Git 忽略。错误和警告不得
  输出完整会话正文、记忆正文、密钥或认证信息。

- **N9：兼容性**  
  现有流式响应、Thinking、工具循环、权限审批、plan-only、MCP、上下文压缩、取消和
  错误恢复行为不得回归。斜杠命令不得进入模型历史。

- **N10：Provider 边界**  
  会话格式、项目上下文和记忆模型保持供应商无关；当前功能只接入并验收 Anthropic，
  不新增 OpenAI 专用实现。

- **N11：可测试性**  
  指令展开、路径拦截、JSONL 提交与修复、会话切换、压缩恢复、时间提醒、记忆索引以及
  退出整理均可通过本地模拟 Provider 测试；CLI、TUI 和斜杠恢复必须执行真实交互式
  端到端验证。

## 不做的事

- OpenAI 或其他 Provider 的专用适配与验收。
- 全局用户记忆、跨项目共享记忆或云端同步。
- 向量数据库、Embedding、关键词检索、相似度算法或自动相关性排序。
- 定时或每若干回合生成记忆；本期只在正常退出时处理。
- 给 `MEMORY.md` 或主题记忆文件提供 `@include`、子索引或多层索引。
- 在普通请求中自动注入全部记忆正文。
- 自动热加载运行期间人工修改的 `YCODE.md` 或记忆文件。
- 发现或合并 `AGENTS.md`、`CLAUDE.md` 等其他项目指令格式。
- `/sessions`、`/delete`、交互式会话选择器或完整的会话管理界面；本期仅实现
  `/resume <session-id>`，其余能力停留在统一管理接口。
- 使用 LLM 生成会话标题；标题只从第一条用户消息确定性生成。
- 会话 meta 文件、数据库索引、全文搜索、标签、收藏、归档和自动清理。
- 自动恢复上次会话；只有显式 `--continue` 或 `/resume` 才恢复。
- 保存流式增量、TUI 渲染事件、失败回合或取消回合。
- 会话文件加密、用户身份隔离、远程备份或多进程并发写入同一会话。
- 断电、系统崩溃、磁盘故障下的强持久化保证。
- 自动记忆变更的人工逐项审批界面。
- 压力测试、性能基准、大规模会话迁移或长期稳定性测试。

## 验收标准

- **AC1（F1、F2）：项目根与指令发现**  
  从项目子目录启动时，YCode 使用最近活动配置所在目录作为项目根；存在 `YCODE.md`
  时自动读取，不存在时正常启动。显式配置路径使用该文件所在目录。

- **AC2（F3）：指令引用**  
  多层 `@include` 按当前位置正确展开；第 5 层允许读取。第 6 层、循环引用、缺失文件、
  绝对路径、`..` 逃逸和符号链接逃逸均阻止启动，并显示来源文件和引用位置。

- **AC3（F4）：指令上下文**  
  每次 Anthropic 请求都包含独立的项目指令上下文块，普通消息历史和 JSONL 中不存在
  该内容。发生上下文压缩或 `/resume` 后，项目指令仍然存在。

- **AC4（F5）：会话管理入口**  
  通过统一会话管理接口可以创建、列出、恢复和删除会话；`.ycode/sessions/` 中每个会话
  只有一个 JSONL，没有 meta 文件。删除活动会话被拒绝，删除非活动会话只影响指定 ID。

- **AC5（F6）：会话 ID**  
  首条用户消息生成包含本地时间和短标题的 ID；中文被保留，空白和 Windows 非法字符
  被清理，标题不超过 32 个字符。同秒重名时生成不同 ID。

- **AC6（F7）：结构化存档**  
  完成包含 Thinking 和工具调用的回合后，JSONL 可以观察到版本、UTC 时间、完整消息及
  提交边界；不存在流式 delta 和 TUI 事件。重新加载后消息内容块和顺序保持一致。

- **AC7（F8）：写前提交**  
  模拟 JSONL 写入或刷新失败时，本轮不进入内存历史，也不产生成功终态；恢复写入后，
  后续完整回合可以正常提交。取消、Provider 错误和轮数超限不会产生已提交回合。

- **AC8（F9）：启动恢复**  
  默认启动创建新会话；`--continue` 恢复时间戳最新的会话；`/resume <session-id>` 恢复
  指定会话且命令不进入历史。不存在或不可恢复的 ID 显示错误，当前会话保持不变。

- **AC9（F9、F14）：会话切换隔离**  
  从已有对话切换到另一会话后，原会话仍可再次恢复；目标历史成为活动历史。模式回到
  `agent`，临时权限清空，上下文失败状态重置，下一请求包含完整模式提醒，应用级工具
  和 MCP 连接保持可用。

- **AC10（F10、F11）：坏行与尾部修复**  
  在 JSONL 中插入无法解析的行并制造不完整尾部后恢复，会显示警告、跳过坏行并只保留
  最后完整提交边界；文件被实际截断，之后可以继续追加和再次恢复。

- **AC11（F11）：工具链修复**  
  构造缺少对应 `tool_result`、调用 ID 不匹配或消息顺序无效的记录时，恢复不会把不完整
  工具链发送给模型，而是截断到此前完整回合。

- **AC12（F12）：恢复压缩检查点**  
  恢复超出阈值的历史时只调用一次压缩。成功后写入检查点，并在下次恢复时使用该摘要
  和后续消息，不重复压缩同一段历史；压缩失败时原文件保留、当前活动会话不变且本次
  恢复失败。

- **AC13（F13）：时间跨度提醒**  
  恢复最后活跃时间超过 24 小时的会话后，第一次模型请求包含一次时间跨度提醒，时间按
  本地格式展示；第二次请求不再包含。未满 24 小时不注入。

- **AC14（F15、F16、F17）：记忆目录与格式**  
  四类主题文件使用正确前缀和 YAML front matter，索引按固定 Markdown 格式指向文件。
  类型、前缀、`name`、`description` 与索引内容不一致时，该条不会成为有效记忆。

- **AC15（F18）：索引注入与按需读取**  
  普通请求只包含 `MEMORY.md` 的有效索引，不包含主题正文。模型调用 `read_file` 后可以
  读取索引指向的具体记忆文件。

- **AC16（F18）：记忆失败隔离**  
  索引缺失时正常对话；格式错误、目标缺失或 front matter 无效时跳过对应条目并警告；
  绝对路径、`..` 和符号链接逃逸不会读取项目外内容，也不会导致整个应用启动失败。

- **AC17（F19、F20）：退出记忆判断**  
  正常退出且存在新成功回合时，隔离的无工具模型请求收到本次运行新增对话、当前索引和
  全部有效记忆正文。模型可以返回无需变更、新建、更新、合并或删除，程序不执行本地
  相似度判断。

- **AC18（F19）：跨切换会话整理**  
  同一次运行中先在会话 A 产生新回合，再切换到会话 B 产生新回合，退出整理请求同时
  包含 A、B 的新增内容及其会话 ID 和时间边界；已有旧历史不重复加入。

- **AC19（F21）：记忆变更安全性**  
  合法变更自动写入且新索引只指向完整文件；删除仅影响索引引用的记忆主题。模拟无效
  路径、类别不符、输出结构错误或写入中断时，原有效索引仍可使用，项目外文件不受影响。

- **AC20（F22）：退出边界**  
  `/exit`、`/quit` 和空闲 `Ctrl+C` 均触发整理；没有新增成功回合时不调用模型。模拟
  模型超时超过 30 秒或调用失败时，YCode 保留原记忆、显示非致命提示并正常退出。

- **AC21（N8）：本地隐私**  
  `.ycode/sessions/` 和 `.ycode/memory/` 默认被 Git 忽略；错误及警告输出中不包含完整
  会话正文、记忆正文、API Key 或认证头。

- **AC22（N9、N10、N11）：兼容与端到端**
