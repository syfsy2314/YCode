# YCode 工具权限安全系统 Spec

## 背景

YCode 已有工作区路径沙箱、READ/WRITE 分类、plan-only 工具限制和执行前参数校验，
但尚未提供危险命令拦截、项目规则、权限模式和人工审批。模型产生的工具参数属于
不可信输入，需要在实际执行前经过统一、可观察且默认安全失败的权限判定。

未来 MCP 工具会由统一工具适配器包装成与本地工具一致的普通工具。本功能不处理 MCP
协议，只保持统一工具执行入口及未知安全分类的保守行为。

## 目标

- 为当前六个本地工具增加统一的执行前权限判断。
- 保留工作区路径沙箱，并增加不可绕过的危险 PowerShell 命令黑名单。
- 支持项目级安全配置、会话临时授权和三档权限模式。
- 对需要询问的调用提供简洁的终端人工确认。
- 让没有可靠安全分类的工具默认询问，为未来统一工具适配保留安全行为。
- 保持实现聚焦，不增加 MCP、系统级 Shell 沙箱、审计平台或通用策略插件框架。

## 功能需求

- **F1：统一权限判定**  
  当前六个本地工具在实际执行前统一经过权限判定。判定结果只有允许、拒绝和询问。
  无法可靠归类的工具按未知类型处理，默认询问。

- **F2：不可绕过的执行边界**  
  plan-only 继续禁止写入和命令工具。文件、搜索工具及命令工作目录必须解析到工作区
  内。符号链接和 Junction 本身不禁止；最终目标位于工作区内时继续普通权限判断，
  最终目标越界、链接损坏或无法解析时拒绝。写入不存在的新文件时检查真实父目录。
  路径沙箱不能通过规则、权限模式或人工授权绕过。

- **F3：危险命令黑名单**  
  `run_command` 在普通权限判断前解析 PowerShell 语法结构，而不是只匹配原始字符串。
  系统拦截已确认的大范围递归删除、磁盘与文件系统破坏、远程内容直接执行、动态或
  编码执行、系统启动与关机破坏、高破坏性 Git 操作，以及针对工作区外或系统位置的
  危险权限与所有权接管。命令别名、大小写、空白、换行和管道变化不能绕过检查。
  解析失败或明确命中时直接拒绝，不提供人工放行。

- **F4：项目安全配置**  
  系统从当前目录向上读取最近的 `.ycode/security.yaml`。配置可以声明启动权限模式
  和有序规则；文件不存在时使用 `default` 模式和空规则。未知工具、未知参数、重复
  规则 ID 或非法配置值导致启动失败，并提供明确错误。

- **F5：规则表达和优先级**  
  项目规则支持 `allow`、`deny` 和 `ask`，按准确工具名和参数条件匹配。字符串条件
  支持精确匹配或 Glob 全匹配，布尔值和数字只支持精确匹配。一条规则只检查其声明的
  参数；工具名不能使用模糊匹配。路径在沙箱校验并解析为真实目标后，转换成工作区
  相对 POSIX 路径进行匹配。决策优先级为：硬安全规则、plan-only 限制、会话规则、
  项目规则、权限模式。项目规则按声明顺序首次命中；会话允许可以覆盖项目规则，但
  不能覆盖硬安全规则或 plan-only。

- **F6：权限模式**  
  `strict` 对所有未匹配工具询问；`default` 自动允许读取和搜索，写入、编辑及命令
  需要询问；`allow` 自动允许所有已可靠分类且未匹配的工具。未知分类在三种模式下
  均默认询问。显式规则和会话允许的优先级高于权限模式。

- **F7：人工审批**  
  询问界面只提供“拒绝”“本次允许”和“本会话允许”。每个需要询问的工具调用单独
  审批；同一模型响应中的调用按模型顺序逐个询问，审批前不得启动工具。审批界面显示
  工具名称、触发原因和规范化后的安全关键参数；文件操作显示路径和操作类型，写入与
  编辑显示有限长度的内容或变更预览，命令工具完整显示命令和工作目录。所有审批结束
  后，获准调用继续使用现有读取并发和写入屏障。拒绝只影响当前调用；相同调用再次
  出现时重新询问。拒绝以结构化工具结果回填模型，不终止整个 Agent 回合。

- **F8：会话允许**  
  会话允许只保存在当前进程中，退出后失效。`read_file` 按真实路径匹配；
  `write_file` 按真实路径和覆盖标记匹配；`edit_file` 按真实路径匹配；`glob` 按
  搜索模式匹配；`grep` 按搜索表达式、真实起始路径、文件模式和大小写选项匹配；
  `run_command` 按首尾去除空白后的完整命令和真实工作目录匹配。分页、结果数量以及
  写入或替换正文不参与会话匹配。未知分类工具按工具名和完整规范化参数精确匹配。
  权限模式切换不清除会话允许，plan-only 仍然优先阻止写入和命令。

- **F9：权限模式交互**  
  启动页和输入区域显示当前权限模式。`/permission` 显示当前模式和可用值；
  `/permission strict|default|allow` 切换当前会话模式；`/permission clear` 清除
  当前会话允许。上述命令不调用模型、不进入对话历史、不修改项目配置。项目配置修改
  后需要重新启动 YCode 才能生效。

- **F10：模型上下文与拒绝结果**  
  当前权限模式通过动态 system 补充告知模型。完整项目规则、黑名单匹配方式和会话
  授权内容不得发送给模型。硬规则、普通规则和用户拒绝产生稳定的结构化错误码和简短
  原因，使模型能够选择安全替代方案。审批选择本身不作为用户消息写入对话历史。

## 非功能需求

- **N1：默认安全失败**  
  权限配置、命令解析、策略判定或审批流程发生异常时，不得继续执行相关工具。启动
  配置错误应明确报告，运行期错误应转换成安全拒绝。

- **N2：决策确定性**  
  相同权限模式、会话状态、项目规则和规范化工具参数必须产生相同判定。规则顺序、
  参数规范化和会话授权匹配方式必须可测试。

- **N3：敏感信息保护**  
  权限提示、错误和动态 system 补充不得暴露完整安全规则、黑名单实现、环境变量、
  密钥或无关文件内容。写入和编辑预览必须限制长度。

- **N4：执行时序安全**  
  工具在获得允许前不得产生副作用。取消审批或 Agent 回合时，不得继续启动等待中的
  工具。已经进入执行阶段的取消行为沿用现有工具取消机制。

- **N5：兼容现有行为**  
  已允许工具继续使用现有参数校验、超时、读取并发、写入屏障、结构化结果、事务回滚
  和终端取消机制。OpenAI 现有纯聊天路径不得因本功能回归。

- **N6：统一工具兼容性**  
  权限检查只依赖供应商无关的统一工具定义和参数，不依赖 Anthropic 或未来 MCP 类型。
  未知安全分类必须保持默认询问行为，并按写入类工具串行调度。

- **N7：可验证性**  
  黑名单类别、路径边界、规则顺序、三档模式、会话允许、拒绝回填、模式命令和终端
  审批流程均需有自动化验证；至少包含真实 Windows ConPTY 端到端场景。

## 不做的事

- 不实现 MCP 客户端、MCP 工具发现、连接或统一工具适配器；未来适配后的工具复用
  统一权限入口。
- 不新增用户目录的全局安全配置，只支持项目级 `.ycode/security.yaml`。
- 不提供项目规则的图形化编辑、终端编辑或自动写入；永久规则由用户手工维护。
- 不实现操作系统级 PowerShell 沙箱、受限账户、容器或网络隔离。
- 不实现持久化安全审计、日志平台、统计面板或审批历史查询。
- 不支持安全配置热加载。
- 不允许通过人工审批、会话规则或项目规则绕过路径沙箱和危险命令黑名单。
- 不自动撤销已经完成的文件修改或命令副作用。
- 不建设通用策略插件框架、远程策略服务或组织级策略分发。
- 不新增或扩展 OpenAI 专用配置、Provider 协议适配或 OpenAI 验收场景；现有纯聊天
  能力只做回归保护。
- 不向模型发送具体项目规则、危险命令匹配细节或会话授权内容。

## 验收标准

- **AC1：统一权限入口**  
  当前六个本地工具在实际执行前均产生明确权限决策；未获允许的工具没有文件、命令
  或其他执行副作用。

- **AC2：硬边界**  
  指向工作区内目标的符号链接和 Junction 可以正常访问；指向工作区外的链接、不可
  解析链接、普通路径越界，以及 plan-only 下的写入和命令调用均被拒绝。任何规则、
  权限模式和会话允许都不能覆盖这些限制。

- **AC3：危险命令**  
  每个已定义危险类别至少有一个典型命令和一个大小写、空白、别名或管道变体被拒绝；
  PowerShell 解析失败时拒绝执行；不属于黑名单的普通命令不会被误判。

- **AC4：项目配置**  
  能发现最近的项目安全配置并加载模式和规则；配置缺失时使用内置默认值；重复 ID、
  未知工具或参数、非法动作和非法匹配条件会阻止启动并显示明确错误。

- **AC5：规则判定**  
  精确匹配、Glob 全匹配、真实路径规范化和首次命中行为符合定义；会话规则、项目规则
  和权限模式之间的优先级通过冲突场景验证。

- **AC6：权限模式**  
  strict、default 和 allow 对读取、写入、命令及未知分类工具产生已约定的允许或询问
  结果；危险黑名单和 plan-only 在所有模式下保持有效。

- **AC7：人工审批**  
  真实终端中能看到工具、原因和关键参数，并完成拒绝、本次允许和本会话允许；批量
  调用按顺序审批，未审批工具不会提前执行，拒绝结果能回填模型并允许 Agent 继续。

- **AC8：会话授权**  
  当前六个工具按各自安全关键参数复用会话授权；未知分类按完整规范化参数匹配；关键
  参数变化后重新询问；`/permission clear` 和进程重启会清除授权。

- **AC9：模式交互和模型上下文**  
  启动页、输入区域及 `/permission` 命令正确显示和切换权限模式；切换不请求模型、
  不进入历史、不修改配置；后续动态 system 补充包含模式摘要但不包含具体规则或授权
  内容。

- **AC10：失败与取消**  
  配置、判定或审批异常采用安全拒绝；Ctrl+C 能取消等待中的审批和当前 Agent 回合，
  且不会启动尚未批准的工具。

- **AC11：回归验证**  
  现有工具参数校验、并发调度、写入屏障、取消、事务、plan-only、提示词系统、
  Anthropic 工具循环和 OpenAI 纯聊天回归测试继续通过；Windows ConPTY 端到端审批
  场景通过。
